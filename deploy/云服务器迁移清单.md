# 云服务器迁移清单

> 目标：把当前跑在个人电脑上的 8 个容器整体搬到云服务器，使 `demo.mabokai.site` 不再依赖本机开关机。
> 本文按「准备 → 初始化 → 部署 → 配置 → 数据 → 域名 → 验证 → 回滚」顺序排列，每一步都是可直接粘贴执行的命令。
> 配套脚本：`deploy/migrate-export.sh`（本机导出）、`deploy/migrate-import.sh`（服务器导入）、`deploy/docker-compose.prod.yml`（端口收敛）。

---

## 0. 先看现状：迁移量到底有多大

以下为 2026-11-09 实测值，不是估算：

| 项目 | 实测值 | 说明 |
|---|---|---|
| 镜像总量 | **约 4.3 GB** | web 233MB + api 1.83GB + worker 1.83GB（同镜像两份）+ 基础镜像 |
| Qdrant 数据 | **7.3 MB**（106 + 2 个点） | 两个集合：`ai4s_papers`、`ai4s_paper_meta` |
| MinIO 数据 | **20 MB**（130 个对象） | papers 2 / figures 77 / provenance 51 |
| Redis 数据 | 8 KB | celery broker，**不需要迁移** |
| 模型缓存 | **2.1 GB** | fastembed/huggingface，可重下，建议拷 |
| 8 容器常驻内存 | **约 1.05 GB** | worker 474M + api 329M 占大头 |
| 实际数据导出包 | **20 MB** | `qdrant.tgz` 3.3M + `minio.tgz` 17M + env |

**结论：数据量极小（20MB），重的是镜像和构建。** 所以迁移的主要风险不是"数据搬不动"，而是「构建失败」和「配置漏改」。

## 1. 三条路线，先定方向

| 路线 | 服务器位置 | 域名备案 | 切换耗时 | 适用 |
|---|---|---|---|---|
| **A（推荐）** | 香港 / 境外 | 不需要 | 半小时 | 现在就要能用，不想等审核 |
| B | 大陆（阿里云/腾讯云） | **必须 ICP 备案** | 备案 1–3 周 | 长期运营、要国内低延迟 |
| C | 只把隧道搬走 | — | 不可行 | 隧道必须在源站，源站就是服务器本身 |

**为什么推荐 A**：`mabokai.site` 目前没有大陆 ICP 备案。大陆服务器对未备案域名提供 Web 服务会被接入商拦截（80/443 直接断），这是硬性限制，跟用什么技术无关。香港/境外服务器没有这个前提，`demo.mabokai.site` 现有配置一个字都不用改，Cloudflare 隧道继续用。

如果你后续一定要上大陆服务器，顺序是：先备案（域名实名已通过，可以提交）→ 备案通过后再迁。别反过来做。

### 1.1 买哪台（2026-11 价格，以结账页为准）

按本项目实测需求（**2 核 4G、磁盘 40G+、境外**）：

| 选项 | 配置 | 价格 | 入口 |
|---|---|---|---|
| **阿里云香港轻量（首选）** | 2核 4G / 80G ESSD / 30M峰值 / 3072G 流量 | **67 元/月**、804 元/年 | https://www.aliyun.com/product/swas |
| 腾讯云香港轻量 | 2核 4G / 60G / 200M峰值 / 无限流量 | 约 60–95 元/月 | https://cloud.tencent.com/product/lighthouse |
| 阿里云香港轻量（低配够用） | 2核 2G / 60G / 30M / 2048G | 34 元/月 | 同上，但**构建会 OOM**，见 3.3 |
| Vultr 香港 | 2核 4G / 80G NVMe | 约 $18–24/月 | https://www.vultr.com/pricing/ |

购买时四个选项必须选对：

1. **地域**：`中国香港`（阿里云购买页默认是北京，要手动切）
2. **镜像**：`系统镜像 → Ubuntu 22.04 LTS`（不要选宝塔/WordPress 应用镜像，用不上）
3. **套餐**：2核 4G（2核 2G 会在 `next build` 阶段被 OOM killer 杀掉）
4. **数据盘**：不需要，80G 系统盘够用

三点提醒：

- 香港轻量**不支持按量付费**，只能包月/包年；想按小时计费得上 ECS/CVM 按量实例，本项目没必要
- 阿里云「免费试用」**不含中国香港**（仅内地 + 伦敦等 21 个地域）
- 30M 峰值带宽对演示完全够：整站首屏约 1MB（含 601K 鹤图），30M 理论 3.7MB/s

## 2. 迁移前准备（本机，约 30 分钟）

### 2.1 代码必须先入库 —— 这是当前最大的坑

实测 `git status` 有 **9 个已修改 + 9 个未跟踪** 文件，其中三个是网站运行的必需品：

```
?? frontend/public/mascot-crane.png     601K   ← 首页 hero 鹤图
?? frontend/public/mascot-avatar.png    231K   ← 问答页头像
?? frontend/src/components/SuggestionChips.tsx  ← 首页推荐问题组件
?? deploy/                                     ← 全部部署脚本
```

**如果直接 `git clone` 到服务器，首页鹤图会 404、问答页头像缺失、部署脚本不存在**——镜像能构建成功，但页面是残的。

```bash
cd /d/workbuddy/2026-10-21-16-54-36
git add -A
git commit -m "chore: 同步部署脚本、视觉资源与 compose 自启配置"
git push origin main
git status --porcelain          # 应为空
```

> 不想动 git 的话，改用 `rsync` 整体同步（见 3.2），但要记得排除 `node_modules`、`.next`、`.env`。

### 2.2 导出数据与配置

```bash
# 默认：qdrant + minio + .env + 基线清单，约 20MB
bash deploy/migrate-export.sh

# 连 2.1G 模型缓存一起（推荐，省掉服务器首次下载）
bash deploy/migrate-export.sh --with-model-cache
```

产物目录 `migration-YYYYMMDD-HHMM/`：

| 文件 | 内容 |
|---|---|
| `qdrant.tgz` | 两个集合的完整向量与 payload |
| `minio.tgz` | 三个桶全部对象 |
| `model_cache.tgz` | 可选，2.1G |
| `env.production` | `.env` 副本，权限 600 |
| `MANIFEST.txt` | **迁移前基线**：106 / 2 点、2 / 77 / 51 对象 |

脚本已把 `migration-*/`、`env.production` 写进 `.gitignore`。

### 2.3 密钥清点

`.env` 共 20 个键，迁移时只有 4 类需要处理：

| 键 | 迁移后动作 |
|---|---|
| `DASHSCOPE_API_KEY` / `OPENAI_API_KEY` | 原样带走，**不要**贴进任何文档或截图 |
| `CLOUDFLARE_TUNNEL_TOKEN` | 若新建隧道则替换；沿用旧隧道则不变 |
| `MINIO_ROOT_PASSWORD` | 现值是 `minioadmin`，公网环境**必须换**（见 5.2） |
| `JUDGE_PASSWORD` | 同上，现值 `ai4s2024`，换掉 |
| `NEXT_PUBLIC_API_URL` | **保持空**。它是 build arg，空值走同源相对路径，经 Nginx 转发才正确 |

### 2.4 选服务器规格

依据实测：

| 项 | 需求 | 说明 |
|---|---|---|
| CPU | 2 核 | 8 容器空闲占 CPU < 1%，LLM 调用是外部 API，不吃本地算力 |
| 内存 | **4 GB 起** | 常驻 1.05G；`next build` + `pip install` 峰值会摸到 3G+，2G 会 OOM |
| 磁盘 | 40 GB 起 | 镜像 4.3G + 构建缓存约 3G + 模型 2.1G + 系统 |
| 系统 | Ubuntu 22.04 / 24.04 | Docker 官方支持最稳 |

只出演示、不构建的话 2C2G 也能跑，但必须在本地构建好镜像再传（见 3.3），否则 99% 会在 `next build` 被 OOM killer 杀掉。

## 3. 服务器初始化（约 15 分钟）

### 3.1 基础环境

```bash
# 以 root 登录后
apt update && apt upgrade -y
apt install -y curl git ca-certificates ufw

# Docker（官方脚本；若拉取慢见 9.2）
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
docker compose version        # 需 v2.24+，prod 覆盖层用到 !reset/!override

# 时区：否则容器日志比本地时间差 8 小时，排查会误判
timedatectl set-timezone Asia/Shanghai

# 防火墙：只开 SSH 和 HTTP/HTTPS。6379/6333/9000 一律不开
ufw allow 22/tcp
ufw allow 80,443/tcp
ufw --force enable

# 2G 内存的机器必须加 swap，否则构建必挂
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 3.2 取代码

```bash
mkdir -p /opt/ai4s && cd /opt/ai4s
git clone https://github.com/mbk200779/ai4s-agent.git
cd ai4s-agent
```

**仓库是公开还是私有会影响这一步**：私有仓库需要先配 Deploy Key 或 PAT。若不想处理，从本机直传：

```bash
# 本机执行；排除构建产物与密钥
rsync -avz --exclude node_modules --exclude .next --exclude .env \
  /d/workbuddy/2026-10-21-16-54-36/ root@<IP>:/opt/ai4s/ai4s-agent/
```

### 3.3 镜像：构建还是传输

| 方案 | 耗时 | 前提 | 建议 |
|---|---|---|---|
| **服务器上构建** | 8–15 分钟 | ≥4G 内存或已加 swap；`backend/Dockerfile` 已用清华源、`frontend/Dockerfile` 已用 npmmirror | **首选**，缓存可复用，后续更新快 |
| 本地 `docker save` 传输 | 传 3.9G，视带宽 10–40 分钟 | 两边架构都是 `linux/amd64`（当前镜像已确认） | 内存 2G 时用这个 |
| CI 构建推镜像仓库 | 一次配置，长期最省 | 需 registry 账号 | 长期维护再做 |

本地构建 + 传镜像的具体命令：

```bash
# 本机
docker save 2026-10-21-16-54-36-api:latest 2026-10-21-16-54-36-worker:latest \
  2026-10-21-16-54-36-web:latest | gzip > ai4s-images.tar.gz
scp ai4s-images.tar.gz root@<IP>:/opt/ai4s/

# 服务器
gunzip -c /opt/ai4s/ai4s-images.tar.gz | docker load
```

注意：镜像名带项目前缀 `2026-10-21-16-54-36-`，这是 compose 项目名（= 目录名）生成的。若服务器上目录叫 `ai4s-agent`，镜像名会变成 `ai4s-agent-api:latest`，`docker load` 的旧名字对不上。**解决办法：服务器上统一把目录命名为 `2026-10-21-16-54-36`，或在 compose 顶层加 `name: ai4s` 并重新构建。**

## 4. 配置调整（部署前必须完成）

### 4.1 落 `.env`

```bash
cd /opt/ai4s/ai4s-agent
cp /opt/ai4s/migration-*/env.production .env
chmod 600 .env
```

### 4.2 必须改的三处

```bash
# 1) MinIO 口令：默认 minioadmin/minioadmin 在公网等于裸奔
sed -i 's/^MINIO_ROOT_PASSWORD=.*/MINIO_ROOT_PASSWORD=<强口令>/' .env

# 2) 评审口令
sed -i 's/^JUDGE_PASSWORD=.*/JUDGE_PASSWORD=<强口令>/' .env

# 3) 确认 API 基址为空（空 = 同源相对路径，经 Nginx 转发）
grep '^NEXT_PUBLIC_API_URL=' .env      # 期望：NEXT_PUBLIC_API_URL=
```

> 改 MinIO 口令只影响**登录凭据**，不影响已有对象；但改完必须和 `api` 容器里的 `MINIO_ACCESS_KEY/SECRET_KEY` 一致——它们都读同一组 `.env`，所以只需要 `docker compose up -d --force-recreate api worker minio`。

### 4.3 用生产覆盖层收敛端口

基础 `docker-compose.yml` 把 6333 / 6379 / 9000-9001 / 8000 / 3000 都映射到了 `0.0.0.0`，这是本机调试的方便，放到公网就是**无密码 Redis、无鉴权 Qdrant、默认口令 MinIO 控制台**全部对互联网开放，通常几小时内就会被扫。

`deploy/docker-compose.prod.yml` 把这些全部收回，只留 `127.0.0.1:8080`（仅本机可访问，供验证用）。已实测覆盖生效：

```
映射条数: 1     →  127.0.0.1:8080 → gateway:80
```

以下命令都要带 `-f` 两层：

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml --profile tunnel up -d
```

建议直接固化进 shell 别名：

```bash
echo "alias dc='docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml'" >> ~/.bashrc
```

> ⏱ **执行时机**：本节命令留到第 5 节数据导入完成后再用。导入脚本内部依赖未收敛的 6333 端口做数据比对，先切覆盖层会导致比对那步连不上库。

### 4.4 环境变量全景（改完自查）

| 变量 | 值 | 作用 |
|---|---|---|
| `QDRANT_URL` | `http://qdrant:6333` | 容器名寻址，迁移后不变 |
| `REDIS_URL` | `redis://redis:6379/0` | 同上 |
| `MINIO_ENDPOINT` | `minio:9000` | 同上 |
| `MINIO_SECURE` | `false` | 容器内明文，**不要改 true** |
| `HF_ENDPOINT` | `https://hf-mirror.com` | 模型下载镜像，境外服务器也建议留着 |
| `HOSTNAME`（web） | `0.0.0.0` | **不能删**，删了健康检查必挂（见 9.3） |

## 5. 数据迁移（约 5 分钟）

### 5.1 导入

```bash
# 本机：传导出包（20MB，含模型缓存约 2.1G）
scp -r /d/workbuddy/2026-10-21-16-54-36/migration-20261109-1240 root@<IP>:/opt/ai4s/

# 服务器
cd /opt/ai4s/ai4s-agent
bash deploy/migrate-import.sh --from /opt/ai4s/migration-20261109-1240
```

脚本会依次：写 `.env`（旧的自动备份）→ 建卷 → 停 `api/worker/qdrant/minio` → 清空并还原 → 起全部服务 → 等 qdrant 就绪 → **打印迁移前后数据比对**。

### 5.2 数据一致性注意

| 数据 | 迁移方式 | 一致性 |
|---|---|---|
| Qdrant | 卷整体 tar（`migrate-export.sh` 打包） | 106 个点规模下，打包过程中的写入可忽略；严谨做法是先 `docker compose stop api worker` 再导出 |
| MinIO | 卷整体 tar | 对象存储按文件存，无事务问题 |
| Redis | **不迁** | 只存 celery 任务队列，历史任务丢失无影响；`redis_data` 卷留空即可 |
| 模型缓存 | 可选 | 不迁则首次启动自动下载，2.1G，视带宽 5–20 分钟 |

### 5.3 校验基准（务必对齐）

迁移前 `MANIFEST.txt` 已记录，迁移后必须一致：

```
ai4s_papers      = 106
ai4s_paper_meta  = 2
papers           = 2
figures          = 77
provenance       = 51
```

```bash
# 服务器上手动复查
curl -sS http://localhost:6333/collections/ai4s_papers | grep -o '"points_count":[0-9]*'
```

> ⚠️ 顺序要求：`migrate-import.sh` 内部用**基础 compose**（端口未收敛）启动服务，所以它能访问 `127.0.0.1:6333` 做比对。**必须先导入、后切生产覆盖层**（第 4.3 节）。如果已经切了覆盖层，先把覆盖层那段 `up` 停掉再导入即可，数据卷不受影响。

## 6. 域名与访问配置

### 6.1 路线 A：沿用 Cloudflare 隧道（推荐，改动最小）

隧道连接的**目的地是容器名**，所以服务器上什么都不用改，只要新起一个 cloudflared 连到同一个 Cloudflare 账号。

**步骤（在 Cloudflare 面板）**：

1. `Tunnels` → `Create a tunnel` → 类型 `Cloudflared` → 命名 `ai4s-cloud`
2. 环境选 `Docker`，复制 `docker run ... --token eyJ...` 整条命令
3. 在**服务器**上执行（不是本机）：

```bash
# 方式一：直接用面板给的 docker run
docker run -d --name ai4s-tunnel-cloud --restart unless-stopped \
  --network 2026-10-21-16-54-36_ai4s-net \
  cloudflare/cloudflared:latest tunnel --no-autoupdate run --token <新token>

# 方式二：写进 .env 后用 compose（推荐，和本机脚本一致）
#   把 CLOUDFLARE_TUNNEL_TOKEN 换成新 token，然后
#   docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml --profile tunnel up -d tunnel
```

> 网络名要确认：`docker network ls | grep ai4s`，若服务器上首次启动，网络名会随目录名变化。隧道容器必须和服务在同一网络，否则 `ai4s-gateway` 这个主机名解析不到。

4. 回到 `ai4s-cloud` 详情页 → `路由` → `+ 添加路由` → **已发布的应用程序** → 子域 `demo` / 域 `mabokai.site` / 路径**留空** / 类型 `HTTP` / URL **`http://ai4s-gateway:80`**

**三个已知坑（都在本机踩过，别重复）**：

| 坑 | 现象 | 处理 |
|---|---|---|
| 选了「私有主机名」 | 公网 502，只有装了 WARP 的设备能开 | 必须选「已发布的应用程序」 |
| URL 不带协议头 | 面板报「服务 URL 格式无效」 | 写 `http://ai4s-gateway:80` |
| 协议值被写进「路径」 | 隧道显示健康但首页 404 | 路径框必须为空，或填 `/` |

5. **切 DNS**：新隧道加好同一主机名后，Cloudflare 会把 `demo` 的 CNAME 指向新隧道 ID。旧隧道那条路由**先不要删**，等 6.3 验证通过后再删，这是回滚的退路。

验证 DNS 指向：

```bash
dig +short demo.mabokai.site CNAME
# 期望：<新隧道ID>.cfargotunnel.com
```

### 6.2 路线 B：Nginx 直接对外（大陆服务器需备案）

```bash
# 1) compose 里 gateway 改成监听 80
#    deploy/docker-compose.prod.yml → ports: ["80:80"]
# 2) 证书：Cloudflare 侧开代理（橙云）时可用 Origin Certificate，或 certbot
apt install -y certbot
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml up -d
# 3) nginx 加 443 server 块，引用证书，80 跳 443
```

大陆服务器务必先完成 ICP 备案，否则 80/443 会被接入商拦截，表现为「域名解析正常但连接被重置」。

### 6.3 切换时序（关键）

```
T-0    服务器全栈起来，隧道注册成功，本地 127.0.0.1:8080 验收通过
T+1    新隧道加好 demo.mabokai.site 路由 → DNS 自动切换
T+2    等 1–2 分钟 DNS 生效，公网验证（第 7 节）
T+5    验证全过 → 删除旧隧道上的同名路由
T+10   本机栈可以停（但建议再留 24 小时）
```

**不要先停本机**。两条隧道同时在线时，Cloudflare 按 DNS 记录的 CNAME 决定走哪条，不会互相抢。

## 7. 上线验证（约 10 分钟）

### 7.1 容器与本地入口

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml ps
# 期望 8 个 Up，web/api/worker/qdrant/minio/redis 为 (healthy)

curl -sS http://127.0.0.1:8080/api/v1/health/
# 期望：{"status":"ok","version":"v1.0.0"}
```

### 7.2 公网四链路

```bash
for p in / /writing /qa /graph /eval /review; do
  printf '%-10s ' "$p"
  curl -sS -o /dev/null -w '%{http_code} %{time_total}s\n' "https://demo.mabokai.site$p"
done
```

### 7.3 最严格的一项：真实 LLM 调用

```bash
curl -sS -X POST https://demo.mabokai.site/api/v1/writing/outline \
  -H 'Content-Type: application/json' \
  -d '{"topic":"检索增强生成综述","top_k":1}' \
  -w '\nhttp=%{http_code} time=%{time_total}s\n'
```

期望 `http=200`、耗时 40–90 秒。**这一条同时验证了**：DNS → Cloudflare → 隧道 → Nginx（`proxy_read_timeout 300s`）→ FastAPI → 外部模型 → Qdrant 检索。任何一环断了都会在这里暴露。

### 7.4 数据与渲染

|---|---|---|
| 向量库 | 5.3 的基线 | 106 / 2 |
| 对象存储 | 5.3 的基线 | 2 / 77 / 51 |

## 8. 回滚方案

三级，越往后代价越大：

| 级别 | 触发场景 | 操作 | 耗时 |
|---|---|---|---|
| **L1 流量回切** | 公网异常、页面报错 | Cloudflare 上把 `demo` 路由加回旧隧道（本机还在跑） | 2 分钟 |
| **L2 版本回退** | 新代码有 bug | `git revert <commit>` → `docker compose build web/api` → `up -d` | 10 分钟 |
| **L3 整站回本机** | 服务器被墙、欠费、崩了 | 本机 `bash deploy/start-all.sh`，DNS 自动指回旧隧道 | 5 分钟 |

**回滚能成立的前提**（迁移前就要保证）：

1. 本机栈**不要拆**，至少保留 24–48 小时
2. 旧隧道的 token 不要作废，`.env` 里的 `CLOUDFLARE_TUNNEL_TOKEN` 保留原值
3. 旧隧道上那条 `demo.mabokai.site` 路由**先别删**
4. 本机的 `migration-*/` 导出包留一份，服务器挂了还能重来

> 注意：同名主机名不能同时挂在两条隧道上——切换时 Cloudflare 会把路由从旧隧道迁到新隧道。所以 L1 回滚的实际动作是「在旧隧道上重新添加 `demo.mabokai.site` 路由」，而不是"它本来就在"。

## 9. 常见问题

### 9.1 构建时容器被杀（OOM）

`next build` 峰值约 2G，`pip install` 约 1.5G。表现是 `Killed` 或 `exit code 137`。

```bash
free -h                    # 先看有没有 swap
docker compose build --progress plain web   # 看停在哪一步
```

对策：加 4G swap（3.1 已含）；或改用本地构建 + `docker save` 传输。

### 9.2 拉取镜像失败

`docker pull` 走的是 Docker Hub，国内经常超时。配置镜像加速：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://docker.1panel.live"] }
EOF
systemctl restart docker
```

（项目里 `minio` 曾用过 `docker.1panel.live/minio/minio` 这个前缀，说明本地已经踩过同一个坑。）

### 9.3 网站在跑但健康检查一直 unhealthy

**已在本机复现并修好，clone 后要确认 `HOSTNAME: "0.0.0.0"` 还在。**

Next.js standalone 默认绑 `$HOSTNAME`，容器里它是容器 ID，于是只监听 `172.x.x.x:3000`，`localhost:3000` 探不通 → web 永远 unhealthy → 依赖它的 gateway/tunnel **根本不启动** → 公网 530。外部经 `web:3000` 访问却是 200，极易误判成"服务正常但域名有问题"。

### 9.4 worker 一直 unhealthy

`celery inspect ping` 自身要 5 秒，加上解释器启动接近 10 秒，`timeout: 10s` 会误判。已调整为 `interval 30s / timeout 25s`。若 `docker compose config` 里还是 10s，说明代码不是最新。

### 9.5 Qdrant 启动报 storage 版本不兼容

镜像锁的是 `qdrant/qdrant:v1.11.0`，**不要图省事改成 `latest`**——storage 格式跨大版本不兼容，旧数据卷会直接打不开。同理 MinIO 锁的是 `RELEASE.2024-06-13T22-53-53Z`。

### 9.6 中文图表变方框

`backend/Dockerfile` 里 `fonts-noto-cjk` 单独成层，已固化。若仍出现方框，说明用的是旧镜像（本地那个曾经的"热补丁容器"），服务器上重新构建即可，不需要再手工拷字体。

### 9.7 上传大 PDF 报 413

Cloudflare 免费版**单次请求体上限 100MB**，Nginx 侧 `client_max_body_size` 也是 `100m`（`deploy/nginx.conf:14`）。两者一致，暂时不会互相打架；若要放宽，必须两边同时改，否则一定有一边先拦。

### 9.8 日志时间差 8 小时

容器默认 UTC。服务器执行 `timedatectl set-timezone Asia/Shanghai` 后，新容器会继承；已在跑的用 `--force-recreate` 重建。

### 9.9 磁盘慢慢满

`/var/lib/docker` 会积累构建缓存和悬空镜像（本项目镜像大，一次构建约 3G 垃圾）。

```bash
docker system df                    # 先看占用
docker image prune -af --filter "until=168h"
docker builder prune -af --filter "until=168h"
```

建议加一条每周 cron。**不要**用 `docker system prune -a --volumes`，会连数据卷一起删。

### 9.10 安全基线

| 项 | 必须做 |
|---|---|
| 端口 | 只开 22 / 80 / 443；6379、6333、9000-9001 一律不外露（第 4.3 节已处理） |
| SSH | 禁用密码登录，改密钥；`PermitRootLogin no` |
| 口令 | MinIO / JUDGE 换掉默认值 |
| 防火墙 | `ufw enable`（3.1 已含） |
| 密钥 | `.env` 权限 600；不要贴群里/文档里；迁移完清掉 `env.production` 的临时副本 |
| 备份 | 服务器上每周 `pg_dump` 类比动作：`migrate-export.sh` 可复用做增量备份 |
