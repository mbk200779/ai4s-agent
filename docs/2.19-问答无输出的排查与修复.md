# 2.19 问答「没有输出」的排查与修复

> 现象：问「RAG 如何缓解大模型幻觉？」，页面上只有一条红色「证据不足」和一句「无法回答。」，
> 正文一片空。检索、精排、生成三段都有耗时，5 个候选片段也在，看起来链路是通的。
> 结论先说：**不是没返回、不是异步没跑完、不是异常被吞**——是"库里没有这段内容"这件事
> 一路没被识别出来，最后让模型自己说了句"无法回答"，而那句话被当成正常答案渲染了。

---

## 1 排查：先逐个排除"链路断了"

| 可能原因 | 怎么验的 | 结论 |
|---|---|---|
| 缺少返回（响应里没有答案字段） | 直接抓 SSE：`docker exec ai4s-api curl -N -X POST .../qa/stream`，数事件帧 | 事件齐全：`stage×8 + retrieval + token×2 + claim + uncertainty + done`。`done.answer` 是 `"无法回答。"`，**不是空串**，所以不是"没返回" |
| 异步未完成（生成还没结束就渲染了） | 看 `done.timings` | `generate 2031ms / ttft 1804ms / total 3980ms`，`done` 在 4 秒内到达，页面上的"正文生成中"也会正常消失。不是异步问题 |
| 异常被吞掉 | `docker logs ai4s-api \| grep -i "error\|traceback"` | 只有两处历史异常，都与问答无关：`index_version.py` 缺 `import json`（已修）、`/review/export` 文件名 latin-1 编码（已修）。问答链路上没有 try/except 把异常吃掉 |
| 数据为空（检索没召回） | 看 `done.citations` | `sources=5`，5 篇论文的片段都在。不是空数据 |
| 条件分支未命中 | 对着 `QAService.ask` 的分支图走一遍 | **命中问题所在**：走的是"正常生成"主干，而"空检索"分支一次都没进 |

链路本身没问题，问题在**判断**：系统认为"这次有证据"，于是让模型去写；模型读完 5 段发现没用，
回了一句"无法回答。"；`build_answer` 把这句记为 `unsupported`；置信度落到"证据不足"。
界面拿到的是一个"有答案字段、但内容是拒答"的结果，于是渲染成一行字。

---

## 2 真原因（四条，都有实测数据）

### 2.1 词面子串命中，把"库里有没有"判成了"有"

`uncertainty._count_hits` 原来用 `if term in hay`。`rag` 因此在 279 个片段里"命中"了 **41 段**——
命中的是 `sto-rag-e`、`ave-rag-e`、`f-rag-ment` 这类词。改成整词判定后是 **0 段**。

后果：判定"最具体的两个词在库里出现过"永远为真，空检索永远判不出来。
（`hallucinations` 一直是 0 段，但判定取的是"两个最稀有的词是否**都**为 0"。）

### 2.2 "检索偏弱"用的是 RRF 融合分，它不可比

`empty_state` 里第二条判据是 `rare_missing and retrieval_weak`，而 `retrieval_weak` 指
"融合原始分 < 阈值"。这次原始分是 **0.032**，阈值 **0.03**——刚好越线，于是判"不弱"。

RRF 分只反映两路名次之和，不反映语义相关度：一个库里完全没答案的问题，照样能凑到 0.03 以上。
拿它当"有没有证据"的尺子，等于用量身高的尺子量体重。

### 2.3 生成之后没有任何兜底

模型输出"无法回答。"之后，流程一路当作正常答案往下走：算 claim、算置信、写 provenance、返回。
没有任何一步问一句"这句话是不是模型在说'我没材料'"。于是同一个事实在界面上表现为
"系统答不出来"，而不是"库里没有 + 你能问什么"。

### 2.4 顺带查出来的两处

- **精排冷启动降级**：`rerank` 超时固定 1500ms。实测 20 对 250 词的正文要 480ms，
  8 线程上同时在建索引/跑嵌入时会翻两三倍，第一次请求就撞超时，整批退回融合原序
  （界面只显示"精排 486ms"，看不出已降级）。
- **推荐问题与语料不匹配**：5 个 chip 里 3 个答不出来（RAG 幻觉、多模态对齐、摘要质量）。
  库内是 Attention / BERT / ViT / LoRA / soliton 五篇，这三问本来就没有答案。

```python
# uncertainty.py —— 整词判定
_TERM_RE: dict[str, re.Pattern[str]] = {}

def _term_hit(term: str, hay: str) -> bool:
    pat = _TERM_RE.get(term)
    if pat is None:
        # 左边界挡住 sto-rag-e，右边界允许复数：paper 里 hallucination / hallucinations 混着写
        pat = re.compile(rf"(?<![a-z0-9]){re.escape(term)}(?:e?s)?(?![a-z0-9])")
        _TERM_RE[term] = pat
    return pat.search(hay) is not None
```

```python
# qa_service.py —— 判据
_DECLINE_HEAD = re.compile(
    r"^(无法回答|无法确定|无法判断|无法给出|没有找到|没有提供|没有提及|未提供|未提及"
    r"|抱歉|很抱歉|对不起|根据(现有|给定|以上|提供|所给))"
)

@classmethod
def _is_model_declined(cls, built: Dict[str, Any]) -> bool:
    claims = built.get("claims") or []
    if any(c.get("status") == "supported" for c in claims):
        return False          # 有一句过校验就不是拒答，别把答案吃掉
    text = (built.get("answer") or "").strip()
    if not text:
        return True           # 空正文 + 零支撑，留着空白没有意义
    if not claims:
        return False
    head = text.lstrip("#>*-• \n\t")[:20]
    return bool(cls._DECLINE_HEAD.match(head))
```

### 4.2 评测集回归（48 题）

- **12 道不可答题：12/12 给出结构化拒答**（`empty.reason=model_declined`，全部 `rejected=True`），
  改前是"模型各自回一句没法答的话"，拒答口径不统一。
- **36 道可答题：33 题正常出答案**（答案非空 + 至少 1 条角标）。3 个例外：
  - `s02`：改前就被空检索拦下（`no_lexical_hit`），与本次改动无关；
  - `s03`：改前模型同样回了"无法回答"（只是当时渲染成一段文字），本次改成卡片；
  - `p04`：偶发，同一问题连跑 3 次全部正常作答（`verified` / `needs_check`），不是稳定回归。

检索指标没有动：空检索门槛的字典口径按原样保留（`rare_missing and retrieval_weak`），
所以 `2.18` 里的 Recall@5 / nDCG 不受影响。

## 5 没做的、以及为什么

- **没加"语义相关性闸门"**（用精排分或 embedding 相似度在生成前拦一道）。
  在评测集上标定过：可答题 top 精排分从 −9.56 到 7.85，不可答题 −11.18 到 +0.9，
  重叠严重；词频信号同样重叠（可答题 p13、s02 两个最稀有词也是 0 命中）。
  任何单点阈值都会同时误杀真答案、漏放假问题。要做就得上一个小分类器，那是另一个工作量。
- **没重跑 2.18 的完整评测**：本次改动不碰检索与排序，只影响"生成之后要不要把拒答转成卡片"，
  Recall@5 / nDCG 不会变；重跑一次 4.5 分钟只为了确认没变，性价比不高。
- **`s02` 那道题仍然是拒答**：`parameter-efficient` / `full-parameter` 两个词在库里是
  连字符写法（`parameter-efficient` 命中 1 段，`full-parameter` 命中 0 段），题目本身问的是
  "跨三篇文献的对比"，现有片段没有汇总句。这是语料问题，不是链路问题。
