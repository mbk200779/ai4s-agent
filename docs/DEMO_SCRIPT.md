# AI4S 学术研究 Agent 答辩演示脚本

> 时长：约 7 分 50 秒（要求 5–8 分钟）　|　分辨率 1920×1080
> 目标：让评委在 8 分钟内理解核心链路，并记住「可验证、可复现、可溯源」三条主线。

---

## 录制前的库状态（先核对，别跳过）

演示用的库是**同一个课题下的 6 篇 Transformer 家族论文，共 314 个片段**：

| # | 论文 | arXiv | 页数 | 片段 | 在演示里的作用 |
|---|---|---|---|---|---|
| 1 | Attention Is All You Need | 本地 PDF | 15 | 30 | 原点；问答段的 Adam β1/β2 就在这篇 p.8 |
| 2 | BERT | 1810.04805 | 16 | 58 | 编码器双向预训练这一支 |
| 3 | Transformer-XL | 1901.02860 | 20 | 91 | 长上下文方案 A：片段循环 + 相对位置 |
| 4 | Reformer | 2001.04451 | 12 | 30 | 长上下文方案 B：LSH 近似全局 |
| 5 | Longformer | 2004.05150 | 17 | 23 | 长上下文方案 C：局部窗口 + 少量全局 token |
| 6 | ViT | 2010.11929 | 22 | 82 | 跨模态：同一套注意力搬到视觉 |

**为什么是这 6 篇，不是随便 5 篇相近的**：3/4/5 三篇都在回答"注意力是 O(n²) 怎么办"，但三条路线互相不认同——Longformer 认为局部窗口够用、全局只要几个 token；Reformer 认为全局注意力可以近似到可用；Transformer-XL 认为必须保留完整历史状态。**这是综述冲突标注的真实素材**，不是编出来的对立。换成一堆同方向的新论文，综述只能写成"研究表明各有优势"。

**演示要现场导入的那篇，必须还没入库。** 建议用 T5 `1910.10683`（21 页），它同属这一族、解析约 1 分钟。如果当天 arXiv 拉不动，走 B 计划：跳到库外推荐段，用那里的一键导入代替（同样能展示解析进度）。

**录制前必做**

```bash
bash deploy/demo-check.sh --with-qa   # 六项检查，输出「可以演示 / 有 N 项注意 / 不通过」
```

再手工确认一件事——**worker 与 api 必须是同一次构建的镜像**：

```bash
docker compose exec -T api    python -c "import inspect;from app.models.entities import Chunk;print('anchors' in inspect.signature(Chunk.__init__).parameters)"
docker compose exec -T worker python -c "import inspect;from app.models.entities import Chunk;print('anchors' in inspect.signature(Chunk.__init__).parameters)"
```

两个都得是 `True`。只重建了 api 没重建 worker 的话，导入会在 structuring 阶段抛 `TypeError: Chunk.__init__() got an unexpected keyword argument 'anchors'`——**表加了列、代码没跟上**，这类错误只在"导入"这一条路径上出现，问答完全正常，最容易到台上才炸。

**全程用 `http://localhost:8080`**，不要用公网域名（实测 1/3~3/3 波动，卡一次就得重录）。

## 0:00 - 0:30 开场：一句话定位

> “大家好，我们做的是面向科研人员的 AI4S 学术研究 Agent。科研工作对准确性要求极高，所以我们的设计主线不是‘答得漂亮’，而是**可验证、可复现、可溯源**。接下来七分钟，我用一条真实的科研阅读路径走一遍：导入论文、问一个细粒度问题、看它怎么在证据不足时承认不足、最后用一次评测证明它可复现。”

**屏幕操作**：打开首页 →「开始使用」，停在论文库页（6 篇已入库，片段数可见）。

---

## 0:30 - 1:20 第一步：论文接入与结构化解析

**讲什么**
> “科研 workflow 从论文开始。这个库里已经有六篇，从 Transformer 原点，到 BERT 的预训练、三篇长上下文的改进、再到 ViT 的跨模态。现在我再拉一篇进来：输入 arXiv ID `1910.10683`。”

> “后端把 PDF 写进 MinIO，派发 Celery 任务异步解析。解析不是简单抽文本，我们把 PDF 拆成六类片段：段落、图表、公式、表格、参考文献、章节节点。公式转 LaTeX，图表抽图并生成 caption。这篇二十页，大概一分钟。”

**为什么这么选**
> “科研问题往往问的是公式、图表、参考文献这些细粒度元素，不是整篇摘要。片段粒度越细，溯源时定位越准——我们库里六篇一共切出 314 个片段，平均每页三个，不是按 500 字硬切的。”

> “另外，解析和检索共用同一套 embedding 实现，所以 api 和 worker 用同一个镜像。版本漂移会让入库向量和查询向量不在同一空间，这类问题极难排查——我今天就刚被这个咬过一次，后面 Q&A 里讲。”

**屏幕操作**
1. 导入区输入 `1910.10683`，点拉取。
2. 指一下清单里状态从「排队中」→「解析中 8/21 页」→「已入库」。
3. **不要等它跑完**，让它在后台继续，直接切到问答。

---

## 1:20 - 3:00 第二步：可溯源问答 + 分级置信

**先问单篇的细粒度问题（40 秒）**
> “问一个细粒度问题：Transformer 训练里 Adam 优化器的 β1 和 β2 分别是多少？”

> “答案不是直接生成的。先做查询理解，再 dense + sparse 双路召回，用 RRF 融合，然后 cross-encoder 精排。每个片段都带 page 和 bbox。模型被强制要求每句话后挂 `[引#N]`，生成后程序逐条校验：ID 不在本次检索结果里，就替换成 `[无依据]`。”

**点引用**
> “点这个 `[引#2]`，右侧直接跳到第 8 页，把对应那一行框出来。每个结论都能在 PDF 里找到原位的 bbox。”

**再问跨篇的对比问题（40 秒，这一段是新增的，也是六篇库的价值所在）**
> “再问一个需要横向比较的：Longformer 和 Reformer 分别用什么办法降低自注意力的计算复杂度？”

> “这次引用落在两篇不同的论文上——Reformer 是局部敏感哈希做近似全局，Longformer 是滑动窗口加少量全局 token。跨篇对比最容易出一类错：把 A 论文的方法安到 B 论文头上。所以我们不仅校验引用 ID 存不存在，还要校验这句话所在的那一篇，和被引片段所属的那一篇是不是同一篇。”

**讲分级置信（技术亮点，务必保留）**
> “这里有个设计我想特别说明。早期我们是二值拒答：分低就整条不答。但科研场景里这是错的——用户需要的不是‘系统有没有信心’，而是‘这句话我能不能直接引用’。所以现在分三档：已验证、需核对、无法回答。”

> “判定看证据句与原句的覆盖率：直引句落在 0.6 到 0.95，跨句改写落在 0.2 到 0.45，中间 0.45 到 0.6 基本没有样本，所以阈值取 0.55——不是取中位数，是把线放在两簇之间的空档里。”

> “只有‘一条证据都没检索到’才完整拒答。以前被吞掉的正确答案，现在带一个‘需核对’标记交回来，判断权在读者手里。”

**屏幕操作**
1. 问 Adam β1 β2，等流式答案，点 `[引#2: Attention Is All You Need p.8]` 看 bbox 高亮。
2. 问 Longformer vs Reformer，指出两条引用分别来自 p.2 和 p.3（不同论文）。
3. 指答案顶部置信徽章。

---

## 3:00 - 3:40 第三步：库外补货

**讲什么**
> “如果库里真的没有呢？我问一个这六篇都答不了的：RAG 如何缓解大模型幻觉。”

> “它不会硬答。先告诉你检索了什么、命中了几个词，然后去 arXiv 找几篇能补进来的论文。每一条都写着：标题命中哪些词、摘要里哪一句最相关，右下角标强/中/弱。”

> “注意这里没有用大模型去写‘相关度 92%’这种没法核对的数字——它只报命中词，因为命中词你可以自己核对。”

**一键导入**
> “点‘一键导入数据库’，按钮就地变成解析进度。几十秒后变成‘N 个片段已入库’，然后点‘用它重问’——同一个问题，这次带着引用答出来了。”

> “这是我们不满足于‘拒答’的地方：解释完为什么不知道，还要给一条能改变下一次结果的路。”

**屏幕操作**
1. 问「RAG 如何缓解大模型幻觉」→ 出现空检索卡片 + 推荐列表。
2. 点一篇的「一键导入数据库」→ 展示进度 → 点「用它重问」。
3. （可选）回论文库页，确认刚才 0:30 导入的 T5 也已入库，片段数 +1 篇。

---

## 3:40 - 4:30 第四步：综述生成

**讲什么**
> “生成文献综述。主题是‘长序列建模：效率与全局信息能否兼得’。”

> “它不是把检索片段换个顺序拼起来。流程是：先抽论断，每条带讨论维度、立场、前提条件；再按观点聚类；然后单独做一次冲突检测；最后分簇撰写。”

**为什么这么选（这段是全场技术含量最高的一段，别赶）**
> “这个主题下三篇论文是真有分歧的。Longformer 的立场是：局部窗口加上少量全局 token 就够了，全局注意力是浪费；Reformer 的立场正相反：用 LSH 把全局注意力近似到可用，比放弃全局更划算；Transformer-XL 走第三条路：不放弃任何位置，用片段循环把历史状态带下去。”

> “关键在于**极性是簇键的一部分**。‘局部窗口足够’和‘必须保留全局’这两句，语义相似度能到 0.9 以上，只按语义聚类必然合并成一个中性簇——那写手只能写出‘研究表明两者各有优势’。把极性放进簇键之后，这两条从聚类那刻起就分属两簇，生成阶段没有‘把它们写在一起’的输出位置。”

**屏幕操作**
1. 综述页输入主题 → 生成（约 1 分钟，可先启动再讲）。
2. 展示分簇结构与冲突块——**指着说这两簇在互相反驳**，这是这套系统最值钱的地方。
3. 点「导出 Markdown」→ 打开文件，指引用对照表。

---

## 4:30 - 5:05 第五步：引用图谱

**讲什么**
> “科研还要看关系。构建引用图谱，节点大小代表引用含金量，边粗细代表关系权重。”

> “这六篇刚好构成一个很典型的结构：五篇都引 Attention，所以它是这个子图里入度最高的节点。但入度高不等于重要——我们不用‘被引次数’当影响力，用 `log1p(influentialCitationCount)` 归一化，低于 0.1 的边标记为应付式引用并过滤。因为被引 500 次里往往包含大量顺手一提。”

**屏幕操作**：构建图谱 → 指 Attention 节点的高入度 → 滚轮缩放、拖拽平移、悬停看数值、点节点跳原文。

---

## 5:05 - 5:55 第六步：写作与绘图

**讲什么**
> “图表用代码生成，不用文生图。matplotlib 代码在 AST 白名单的受限环境里执行，请求内容做 SHA256 缓存。这样同输入必然同输出，而且图表自带数据来源标注。”

> “文生图做不到这一点：同 prompt 两次跑都不一样，没法审稿复现。科研插图必须能回答‘这张图是用什么数据、什么代码画的’。”

**屏幕操作**：写作页 → 绘图辅助 → 生成 → 展示 PNG 与代码。

---

## 5:55 - 7:15 第七步：一键评测与 diff=0

**讲什么（口径必须准确，别说过头）**
> “最后是可复现性验证。评测集是 4 篇赛题 PDF 上的 48 道题，覆盖事实点、对比、综述、导航四种题型，另外放了不可答题检验拒答。”

> “执行 `make eval`，脚本先检查服务健康，再跑题集，输出 Recall、引用命中率、拒答率、延迟，以及最关键的 `output_hash`。我再跑一次，两次哈希一致，diff=0。”

> “这里我要如实说明一点：默认配置下评测走的是缓存兜底模式，用来验证**流程与哈希的可复现性**；真实检索指标在技术文档第 6 章——五组基线同链路对比，混合加精排的 Recall@5 是 0.8333，可分性 AUC 从 0.5 提到 0.78。我不想拿一个‘准确率 100%’的数字糊弄过去，因为那是兜底答案的分数。”

**为什么这么选**
> “`temperature=0` 消除了采样随机性，但 API 网关和模型 patch 仍可能带来微小差异。我们把输出按问题哈希缓存，让‘可复现’从依赖模型变成可验证的工程保证。技术文档里我区分了两层：检索可复现是工程保证，生成可复现依赖缓存。”

**屏幕操作**
1. 终端 `make eval`。
2. 展示报告四项指标。
3. 再跑一次，高亮两次 `output_hash` 相同。

---

## 7:15 - 7:50 收尾：三条主线

> “最后总结三条主线：
> 1. **可验证**——每句带 `[引#N]`，无效引用显性化，证据不足分三档告诉你；
> 2. **可溯源**——点引用回跳 PDF 原位，bbox 高亮；
> 3. **可复现**——检索确定性 240 次重放一致，评测两次 diff=0。
>
> 我们也把短板写在文档里：对比题召回偏弱、引用粒度只到页不到句、库外推荐只有词面相关性。这些是下一阶段的输入。
>
> 谢谢大家。”

## 答辩 Q&A 预备

| 可能的问题 | 回答要点 |
|---|---|
| 评测准确率 100% 是真的吗？ | 默认是缓存兜底模式的流程验证。真实指标见技术文档 6.2：五组基线同链路对比，混合+精排 Recall@5 0.8333，本系统 MRR 0.6005 最优。兜底分数不作为能力证明。 |
| 为什么不用学习式融合权重？ | RRF 无参数、可解释、可复现。融合的收益不在 Recall（0.75 vs 纯 BM25 0.8056），在可分性 AUC 0.5→0.78——这决定了阈值和拒答是否可讨论。 |
| 置信阈值 0.55 怎么来的？ | 实测直引句覆盖 0.6~0.95、改写句 0.2~0.45，0.45~0.6 之间无样本。取空档中点，不是取中位数。 |
| 541 页书怎么保证不 OOM？ | 30 页子任务 + group/chord，图片直传 MinIO，子任务只返回轻量元数据；超 80 页自动关视觉模型。历史实测 8 分 46 秒。 |
| 引用准确率有多高？ | 人工抽检 17 条可判引用，严格准确率 76.47%。错误主要是「引对论文引错页」，所以下一步做句级对齐。 |
| 换 embedding 模型要重灌全库吗？ | 不需要。索引版本化的单位是 collection，签名只含影响向量的因素；后台建新集合 → 从 SQLite 重放 → 校验 → 切路由，不停服。 |
| 挂了 Qdrant 怎么办？ | 索引可从 SQLite 的 chunks 表完整重建。这是真实踩过的坑：Qdrant 1.11 的 sparse 索引在高频 upsert+delete 后 panic（读正常、写全 500），修法是绕开坏段重建。 |
| **为什么库里 6 篇却只答出 3 篇？**（真实故障，被问就直说） | 索引写入和检索读的不是同一个 collection：新论文写进了旧集合，检索走的是版本化集合，于是「库里有、搜不到」。修法是从 SQLite 的 chunks 表重建当前版本索引，314 片段一次对齐。这件事让我们在文档里补了一条铁律：**写入必须跟随路由，重建可以显式指定版本**。 |
| 和直接问 ChatGPT 有什么区别？ | 三个可测量的差别：引用可回跳 bbox、置信分三档、检索与评测可复现。ChatGPT 给不了「这句话出处是第 8 页这个框」。 |
| 只有 arXiv，覆盖面够吗？ | 不够。库外补货目前只有 arXiv，非 arXiv 期刊搜不到。扩源的前提是先解决「怎么入库」，否则会变成一串导不进来的链接。 |
| 为什么不做 RAG 之外的花活？ | 科研场景的瓶颈是「验证成本」不是「生成质量」。把力气花在引用校验、置信分档、可复现上，收益比换更大模型更直接。 |

## 台上应急（每条 30 秒内能救回来）

| 现象 | 处置 |
|---|---|
| 导入卡在「解析中」不动 | 说“它在后台跑，我们先看别的”，直接切问答；结束前回来看一眼 |
| 问答返回「证据不足」 | 换脚本里的对比题；或指该卡片说“这正是分级拒答在工作” |
| 图谱加载 502 | 服务刚重启，稍等 10 秒重试；不要现场重启容器 |
| 公网域名打不开 | 本来就不用公网域名；若评委扫码，给局域网 `http://10.110.32.40:8080` |
