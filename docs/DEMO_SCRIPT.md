# AI4S 学术研究 Agent 答辩演示脚本

> 时长：约 7 分 50 秒（要求 5–8 分钟）　|　分辨率 1920×1080
> 目标：让评委在 8 分钟内理解核心链路，并记住「可验证、可复现、可溯源」三条主线。

**录制前必做**

```bash
bash deploy/demo-check.sh --with-qa   # 六项检查，输出「可以演示 / 有 N 项注意 / 不通过」
```

**全程用 `http://localhost:8080`**，不要用公网域名（实测 1/3~3/3 波动，卡一次就得重录）。

---

## 0:00 - 0:30 开场：一句话定位

> “大家好，我们做的是面向科研人员的 AI4S 学术研究 Agent。科研工作对准确性要求极高，所以我们的设计主线不是‘答得漂亮’，而是**可验证、可复现、可溯源**。接下来七分钟，我用一条真实的科研阅读路径走一遍：导入论文、问一个细粒度问题、看它怎么在证据不足时承认不足、最后用一次评测证明它可复现。”

**屏幕操作**：打开首页，点「开始使用」进入论文库导入区。

---

## 0:30 - 1:25 第一步：论文接入与结构化解析

**讲什么**
> “科研 workflow 从论文开始。支持本地 PDF 上传，也支持输入 arXiv ID 直接拉取。我输入 `1706.03762`。后端把 PDF 写入 MinIO，派发 Celery 任务异步解析。”

> “解析不是简单抽文本。我们把 PDF 拆成六种片段：段落、图表、公式、表格、参考文献、章节节点。公式转 LaTeX，图表抽图并生成 caption。长文档会按 30 页切成子任务并行处理，541 页的书也能跑完，实测 8 分 46 秒。”

**为什么这么选**
> “科研问题往往问的是公式、图表、参考文献这些细粒度元素，不是整篇摘要。片段粒度越细，溯源时定位越准。而且解析和检索共用同一套 embedding 实现，所以 api 和 worker 用同一个镜像——版本漂移会让入库向量和查询向量不在同一空间，这类问题极难排查。”

**屏幕操作**
1. 导入区输入 arXiv ID（或直接选一篇已在库的），点拉取。
2. 同一个页面下方就是论文清单，状态从「解析中」变成「已入库」，片段数增加。

---

## 1:25 - 3:05 第二步：可溯源问答 + 分级置信

**讲什么**
> “问一个细粒度问题：Transformer 训练里 Adam 优化器的 β1 和 β2 分别是多少？”

> “答案不是直接生成的。先做查询理解，再 dense + sparse 双路召回，用 RRF 融合，然后 cross-encoder 精排。每个片段都带 page 和 bbox。模型被强制要求每句话后挂 `[引#N]`，生成后程序逐条校验：ID 不在本次检索结果里，就替换成 `[无依据]`。”

**点引用**
> “点这个 `[引#2]`，右侧直接跳到第 8 页，把对应那一行框出来。评委可以看到，每个结论都能在 PDF 里找到原位的 bbox。”

**讲分级置信（技术亮点，务必保留）**
> “这里有个设计我想特别说明。早期我们是二值拒答：分低就整条不答。但科研场景里这是错的——用户需要的不是‘系统有没有信心’，而是‘这句话我能不能直接引用’。所以现在分三档：已验证、需核对、无法回答。”

> “判定看证据句与原句的覆盖率：直引句落在 0.6 到 0.95，跨句改写落在 0.2 到 0.45，中间 0.45 到 0.6 基本没有样本，所以阈值取 0.55——不是取中位数，是把线放在两簇之间的空档里。”

> “只有‘一条证据都没检索到’才完整拒答。这带来的变化是：以前被吞掉的正确答案现在会带一个‘需核对’标记交回给用户，判断权在读者手里。”

**屏幕操作**
1. 输入问题，等流式答案出来。
2. 点 `[引#2: Attention Is All You Need p.8]` → PDF 弹出并高亮。
3. 指出答案顶部的置信徽章（已验证 / 需核对）。

---

## 3:05 - 3:45 第三步：库外补货

**讲什么**
> “如果库里真的没有呢？我问一个库里没有的问题。”

> “它不会硬答。先告诉你检索了什么、命中了几个词，然后去 arXiv 找几篇能补进来的论文。每一条都写着：标题命中哪些词、摘要里哪一句最相关，右下角标强/中/弱。”

> “注意这里没有用大模型去写‘相关度 92%’这种没法核对的数字——它只报命中词，因为命中词你可以自己核对。”

**一键导入**
> “点‘一键导入数据库’，按钮就地变成解析进度。四十秒后变成‘25 个片段已入库’，然后点‘用它重问’——同一个问题，这次带着引用答出来了。”

> “这是我们不满足于‘拒答’的地方：解释完为什么不知道，还要给一条能改变下一次结果的路。”

**屏幕操作**
1. 问「RAG 如何缓解大模型幻觉」→ 出现空检索卡片。
2. 点一篇的「一键导入数据库」→ 展示进度 → 点「用它重问」。

---

## 3:45 - 4:35 第四步：综述生成

**讲什么**
> “生成文献综述。主题是‘Transformer 在机器翻译中的应用’。”

> “它不是把检索片段换个顺序拼起来。流程是：先抽论断，每条带讨论维度、立场、前提条件；再按观点聚类；然后单独做一次冲突检测；最后分簇撰写。”

**为什么这么选**
> “关键在于**极性是簇键的一部分**。‘LoRA 匹配全量微调’和‘LoRA 不如全量微调’这两句，语义相似度能到 0.9 以上，只按语义聚类必然合并成一个中性簇——那写手只能写出‘研究表明两者各有优势’。把极性放进簇键之后，这两条从聚类那刻起就分属两簇，生成阶段没有‘把它们写在一起’的输出位置。”

**屏幕操作**
1. 综述页输入主题 → 生成（约 1 分钟，可先启动再讲）。
2. 展示分簇结构与冲突块。
3. 点「导出 Markdown」→ 打开文件，指引用对照表。

---

## 4:35 - 5:15 第五步：引用图谱

**讲什么**
> “科研还要看关系。构建引用图谱，节点大小代表引用含金量，边粗细代表关系权重。”

> “我们不用‘被引次数’当影响力，用 `log1p(influentialCitationCount)` 归一化，低于 0.1 的边标记为应付式引用并过滤。因为被引 500 次里往往包含大量顺手一提。”

**屏幕操作**：构建图谱 → 滚轮缩放、拖拽平移、悬停看数值、点节点跳原文。

---

## 5:15 - 6:10 第六步：写作与绘图

**讲什么**
> “图表用代码生成，不用文生图。matplotlib 代码在 AST 白名单的受限环境里执行，请求内容做 SHA256 缓存。这样同输入必然同输出，而且图表自带数据来源标注——文生图做不到这一点，同 prompt 两次跑都不一样，没法审稿复现。”

**屏幕操作**：写作页 → 绘图辅助 → 生成 → 展示 PNG 与代码。

---

## 6:10 - 7:20 第七步：一键评测与 diff=0

**讲什么（口径必须准确，别说过头）**
> “最后是可复现性验证。评测集是 4 篇赛题 PDF 上的 48 道题，覆盖事实点、对比、综述、导航四种题型，另外放了不可答题检验拒答。”

> “执行 `make eval`，脚本先检查服务健康，再跑题集，输出 Recall、引用命中率、拒答率、延迟，以及最关键的 `output_hash`。我再跑一次，两次哈希一致，diff=0。”

> “这里我要如实说明一点：默认配置下评测走的是缓存兜底模式，用来验证**流程与哈希的可复现性**；真实检索指标在技术文档第 6 章——五组基线同链路对比，混合加精排的 Recall@5 是 0.8333，可分性 AUC 从 0.5 提到 0.78。我不想拿一个‘准确率 100%’的数字糊弄过去，因为那是兜底答案的分数。”

**为什么这么选**
> “`temperature=0` 消除了采样随机性，但 API 网关和模型 patch 仍可能带来微小差异。我们把输出按问题哈希缓存，让‘可复现’从依赖模型变成可验证的工程保证。技术文档里我区分了两层：检索可复现是工程保证，生成可复现依赖缓存。”

**屏幕操作**
1. 终端 `make eval`。
2. 展示报告四项指标。
3. 再跑一次，高亮两次 `output_hash` 相同。

---

## 7:20 - 7:50 收尾：三条主线

> “最后总结三条主线：
> 1. **可验证**——每句带 `[引#N]`，无效引用显性化，证据不足分三档告诉你；
> 2. **可溯源**——点引用回跳 PDF 原位，bbox 高亮；
> 3. **可复现**——检索确定性 240 次重放一致，评测两次 diff=0。
>
> 我们也把短板写在文档里：对比题召回偏弱、引用粒度只到页不到句、库外推荐只有词面相关性。这些是下一阶段的输入。
>
> 谢谢大家。”

## 答辩 Q&A 预备

| 可能的问题 | 回答要点 |
|---|---|
| 评测准确率 100% 是真的吗？ | 默认是缓存兜底模式的流程验证。真实指标见技术文档 6.2：五组基线同链路对比，混合+精排 Recall@5 0.8333，本系统 MRR 0.6005 最优。兜底分数不作为能力证明。 |
| 为什么不用学习式融合权重？ | RRF 无参数、可解释、可复现。而且实测融合的收益不在 Recall（0.75 vs 纯 BM25 0.8056），在可分性 AUC 0.5→0.78——这决定了阈值和拒答是否可讨论。 |
| 置信阈值 0.55 怎么来的？ | 实测直引句覆盖 0.6~0.95、改写句 0.2~0.45，0.45~0.6 之间无样本。取空档中点，不是取中位数。 |
| 541 页书怎么保证不 OOM？ | 30 页子任务 + group/chord，图片直传 MinIO，子任务只返回轻量元数据；超 80 页自动关视觉模型。实测 8 分 46 秒。 |
| 引用准确率有多高？ | 人工抽检 17 条可判引用，严格准确率 76.47%。错误主要是「引对论文引错页」，所以下一步做句级对齐。 |
| 换 embedding 模型要重灌全库吗？ | 不需要。索引版本化的单位是 collection，签名只含影响向量的因素；后台建新集合 → 从 SQLite 重放 → 校验 → 切路由，不停服。 |
| 挂了 Qdrant 怎么办？ | 索引可从 SQLite 的 chunks 表完整重建，实测 30 片段 21 秒。这是真实踩过的坑：Qdrant 1.11 的 sparse 索引在高频 upsert+delete 后 panic，读正常写全 500。 |
| 和直接问 ChatGPT 有什么区别？ | 三个可测量的差别：引用可回跳 bbox、置信分三档、检索与评测可复现。ChatGPT 给不了「这句话出处是第 8 页这个框」。 |
| 只有 arXiv，覆盖面够吗？ | 不够。库外补货目前只有 arXiv，非 arXiv 期刊搜不到。扩源的前提是先解决「怎么入库」，否则会变成一串导不进来的链接。 |
| 为什么不做 RAG 之外的花活？ | 科研场景的瓶颈是「验证成本」不是「生成质量」。把力气花在引用校验、置信分档、可复现上，收益比换更大模型更直接。 |
