# AI4S 学术研究 Agent 答辩演示：设计与取舍

> **这份文档讲"为什么这么录"，逐字稿在根目录 `演示视频录制脚本.md`。**
> 录制时把那一份放在第二块屏幕上照念即可；本文档用于答辩时解释设计决策，以及应对提问。
>
> 时长 7 分 50 秒（要求 5–8 分钟）　|　分辨率 1920×1080　|　全程 `http://localhost:8080`

---

## 一、库里为什么是这 6 篇

演示用的库是**同一个课题下的 6 篇 Transformer 家族论文，共 314 个片段**：

| # | 论文 | arXiv | 片段 | 在演示里的作用 |
|---|---|---|---|---|
| 1 | Attention Is All You Need | 本地 PDF | 30 | 原点；第 3 段的层数问题、第 7 段的基石节点都在这篇 |
| 2 | BERT | 1810.04805 | 58 | 编码器双向预训练这一支 |
| 3 | Transformer-XL | 1901.02860 | 91 | 长上下文方案 A：片段循环 + 相对位置 |
| 4 | Reformer | 2001.04451 | 30 | 长上下文方案 B：LSH 近似全局 |
| 5 | Longformer | 2004.05150 | 23 | 长上下文方案 C：局部窗口 + 少量全局 token |
| 6 | ViT | 2010.11929 | 82 | 跨模态：同一套注意力搬到视觉 |

**为什么不随便找 5 篇相近的**：3/4/5 三篇都在回答"注意力是 O(n²) 怎么办"，但三条路线互不认同——Longformer 认为局部窗口够用、全局只要几个 token；Reformer 认为全局注意力可以近似到可用；Transformer-XL 认为必须保留完整历史状态。**这是跨篇对比与冲突检测的真实素材**，换成一堆同方向的新论文，问答只能问出"各有优势"，综述也只能写成"研究表明"。

## 二、每个演示点的取舍

### 段 2 现场导入 T5（1910.10683）

演示要现场导入的那篇，**必须还没入库**。T5 同属这一族、约 20 页、解析约 1 分钟，够展示进度又不至于等太久。

提前导了会命中"已解析文件，秒级复用"，进度条就没了——所以录制前**不要**预热这一篇。

如果当天 arXiv 拉不动：不重试，直接把失败反馈当素材（"它不会假装成功"），第 9 段回来时列表里是「解析失败」，补一句"失败也留了记录"。

### 段 3 为什么问"编码器解码器各多少层"

原始脚本问的是 Adam 的 β1/β2。实测这个问题的答案会先引到 ViT 第 5 页（ViT 复述了同一组超参），问"Transformer"却引 ViT，观感上像跑偏；而且 ViT 里那处是块级匹配，角标点开是整段而不是一句。

换成层数问题后：答案一行、4 秒返回、置信是**已验证**、角标落在 `Attention Is All You Need p.3` 的 Table 1 上——最短路径把"点角标→跳回原文"这件事录清楚。

### 段 4 为什么必须问跨篇对比

实测这句把两种置信同时演了出来：Longformer 那句是直引（**已验证**），Reformer 那句由两处片段拼接（**需核对**）。不用刻意设计，颜色自己就分开了。

跨篇对比还牵出引用校验的第二层：不只校验引用编号存不存在，还要校验"这句话所在的论文"和"被引片段所属的论文"是否同一篇——这是防"把 A 的方法安到 B 头上"的那道闸。

### 段 5 问句里为什么带英文词

库外检索走的是**词面匹配**，不是语义：它只取问句里的拉丁词去 arXiv 查，不调模型（这样 LLM 额度耗尽时这条路径仍然可用，而这恰恰是最需要它的时刻）。

所以：

- `RAG 如何缓解大模型幻觉？` → 只有一个词 `rag`，arXiv 返回空 → `no_result`
- `retrieval augmented generation 为什么会产生 hallucination？` → 四个词 → 返回 5 篇，全部「强」，首篇 `MultiRAG`（2508.03553）

这不是 bug，是这条路径的设计边界：**它只承诺"词面对上了"，不承诺"语义相关"**，界面上也照实这么写。

### 段 6 综述主题换成"能力边界与适用条件"

实测三个主题的产出：

| 主题 | 文献 | 结论 | 观点簇 | 确认冲突 | 耗时 |
|---|---|---|---|---|---|
| 长序列建模：效率与全局信息能否兼得 | 2 | 7 | 6 | **0** | 45 s |
| 自注意力机制的复杂度与长序列建模 | 4 | 8 | 8 | **0** | 61 s |
| **Transformer 架构的能力边界与适用条件** | **4** | **17** | **15** | **1** | 81 s |

选第三个：它同时给出"观点簇"和"1 处被确认的条件性分歧"（ViT 相对 ResNet 的准确率，支持 vs 反对，轴相似度 0.794），两个卖点一次演完。而且它是页面上的第一个推荐芯片，点一下就有，不用手打。

**冲突为什么会是 1 而不是更多**：只有同一维度上出现相反立场才标冲突。这 15 个观点里有 15 个是单篇支持，界面会主动标注"仅单篇支持"——**证据强度只有这么多，就说这么多**，不凑"多项研究表明"。

### 段 7 为什么默认看"库内关系"

图谱页有两个标签。**库内关系**是本地计算（PageRank + 正文提及），断网也能出图，9 节点 8 边，Attention 的 PageRank 是 0.3506，其余 5 篇各 0.1299——差距一眼能看见。

**外部引用网络**要实时打 OpenAlex，网络一抖就红。所以只在兜底时才用它。

一个已知瑕疵要避开：`Jonas Gehring, Michael Auli…` 那个灰色节点，是参考文献抽取把作者行误当标题（参考文献字段完整度问题，不是匹配问题）。录的时候不要把鼠标停上去。

### 段 9 为什么不在网页上跑 `make eval`

网页的「运行新评测」是**健康与可复现性检查**（0.16 秒返回四项，含检索两次的片段编号比对），不是完整题集评测。完整指标（Recall@5、MRR、AUC）在技术文档第六章，用 `make eval` 跑。

这个区分要在台上说清楚，否则会被问"你那个 100% 准确率怎么来的"。准确口径是：

- 网页四项检查证明的是**工程可复现**（服务健康 + 检索确定性）
- `make eval` 默认配置走缓存兜底，验证的是**流程与哈希的可复现**
- 真实检索指标：混合 + 精排 Recall@5 = 0.8333，MRR 0.6005，可分性 AUC 0.5 → 0.78

## 三、录制前必做

```bash
bash deploy/demo-check.sh --with-qa      # 六项检查，末尾输出「可以演示」
```

再确认 worker 与 api 是同一份镜像（两条都得是 `True`）：

```bash
docker compose exec -T api    python -c "import inspect;from app.models.entities import Chunk;print('anchors' in inspect.signature(Chunk.__init__).parameters)"
docker compose exec -T worker python -c "import inspect;from app.models.entities import Chunk;print('anchors' in inspect.signature(Chunk.__init__).parameters)"
```

只重建了 api 没重建 worker 的话，导入会在 structuring 阶段抛 `TypeError: Chunk.__init__() got an unexpected keyword argument 'anchors'`——**表加了列、代码没跟上**。这类错误只在"导入"这条路径上出现，问答完全正常，最容易到台上才炸。

**全程用 `http://localhost:8080`**：公网 `demo.mabokai.site` 本机直连有波动（1/3~3/3 成功），卡一次就得重录。

## 四、答辩 Q&A 预备

| 可能的问题 | 回答要点 |
|---|---|
| 评测准确率 100% 是真的吗？ | 网页那四项是健康与可复现性检查，不是题集准确率。真实指标见技术文档 6.2：五组基线同链路对比，混合+精排 Recall@5 0.8333，本系统 MRR 0.6005 最优。兜底分数不作为能力证明。 |
| 为什么不用学习式融合权重？ | RRF 无参数、可解释、可复现。融合的收益不在 Recall（0.75 vs 纯 BM25 0.8056），在可分性 AUC 0.5→0.78——这决定了阈值和拒答是否可讨论。 |
| 置信阈值 0.55 怎么来的？ | 实测直引句覆盖 0.6~0.95、改写句 0.2~0.45，0.45~0.6 之间无样本。取空档中点，不是取中位数。 |
| 引对了但标"需核对"，判定是不是不准？ | 反过来看：那句是由两处片段拼接的推断，不是直引。标签的作用不是判对错，是告诉你"这句能不能直接引"。 |
| 综述为什么只有 4 篇？ | 综述的候选池按主题检索后逐篇取样，主题越窄命中的论文越少。这是可调参数（`review_pool_per_paper` / `review_pool_max_chunks`），为了控时演示按默认配置跑。 |
| 库里 6 篇为什么推荐的全是库外？ | 问的是 RAG 与幻觉，库里这 6 篇（Transformer 家族）本来就没有相关内容。这正是第 5 段要演的场景：不硬答，去库外补。 |
| 541 页书怎么保证不 OOM？ | 30 页子任务 + group/chord，图片直传 MinIO，子任务只返回轻量元数据；超 80 页自动关视觉模型。历史实测 8 分 46 秒。 |
| 引用准确率有多高？ | 人工抽检 17 条可判引用，严格准确率 76.47%。错误主要是「引对论文引错页」，所以下一步做句级对齐。 |
| 换 embedding 模型要重灌全库吗？ | 不需要。索引版本化的单位是 collection，签名只含影响向量的因素；后台建新集合 → 从 SQLite 重放 → 校验 → 切路由，不停服。 |
| 挂了 Qdrant 怎么办？ | 索引可从 SQLite 的 chunks 表完整重建。这是真实踩过的坑：Qdrant 1.11 的 sparse 索引在高频 upsert+delete 后 panic（读正常、写全 500），修法是绕开坏段重建。 |
| 为什么库里 6 篇却只答出 3 篇？（真实故障，被问就直说） | 索引写入和检索读的不是同一个 collection：新论文写进了旧集合，检索走的是版本化集合，于是"库里有、搜不到"。修法是从 SQLite 的 chunks 表重建当前版本索引，314 片段一次对齐。这件事让我们补了一条铁律：**写入必须跟随路由，重建可以显式指定版本**。 |
| 和直接问 ChatGPT 有什么区别？ | 三个可测量的差别：引用可回跳 bbox、置信分三档、检索与评测可复现。ChatGPT 给不了"这句话出处是第 8 页这个框"。 |
| 只有 arXiv，覆盖面够吗？ | 不够。库外补货目前只有 arXiv，非 arXiv 期刊搜不到。扩源的前提是先解决"怎么入库"，否则会变成一串导不进来的链接。 |
| 为什么不做 RAG 之外的花活？ | 科研场景的瓶颈是"验证成本"不是"生成质量"。把力气花在引用校验、置信分档、可复现上，收益比换更大模型更直接。 |

## 五、台上应急

| 现象 | 处置 |
|---|---|
| 导入卡在「解析中」不动 | 说"它在后台跑，我们先看别的"，直接切问答；结束前回来看一眼 |
| 问答返回「需核对」 | 当作正面素材讲：判断权交回读者，而不是假装确定 |
| 综述「冲突 0」 | 念兜底句"观点分散时不硬造对立"，不要提"应该有一个" |
| 图谱 502 | 服务刚重启，等 10 秒重试；不要现场重启容器 |
| 公网域名打不开 | 本来就不用公网域名；若评委扫码，给局域网 `http://10.110.32.40:8080` |
| 某一段反复失败 | 分段录、单独重录那一段再拼，不要整条重来 |
