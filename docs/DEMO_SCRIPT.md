# AI4S 学术研究 Agent 答辩演示脚本

> 时长：约 7 分 30 秒  
> 目标：让评委在 8 分钟内理解核心链路，并记住“可验证、可复现、可溯源”三条主线。

---

## 0:00 - 0:30 开场：一句话定位

**讲什么**：
> “大家好，我们做的是面向科研人员的 AI4S 学术研究 Agent。科研工作对准确性要求极高，所以我们的设计主线不是‘答得漂亮’，而是**可验证、可复现、可溯源**。”

**屏幕操作**：打开首页 `http://localhost:3000`，展示上传页。

---

## 0:30 - 1:30 第一步：论文接入与结构化解析

**讲什么**：
> “科研 workflow 从论文开始。我们支持两种方式：上传本地 PDF，或者输入 arXiv ID 拉取。这里我输入 `1706.03762`，点击拉取。后端会把它写入 MinIO，并派发 Celery 任务做异步解析。”

> “解析不是简单抽文本。我们把 PDF 拆成六种 fragment：段落、图表、公式、表格、参考文献、章节节点。公式会转成 LaTeX，图表会抽图并生成 caption。这里我选 541 页的书，会按 30 页一个子任务并行解析，避免超时和 OOM。”

**为什么这么选**：
> “之所以拆这么细，是因为科研问题往往问的是公式、图表、参考文献这些细粒度元素，而不是整篇摘要。fragment 粒度越细，溯源时定位越准。”

**屏幕操作**：
1. 在首页输入 arXiv ID，点击“拉取并解析”。
2. 切到“论文列表”页（或展示后台任务状态），显示解析完成。

---

## 1:30 - 3:00 第二步：可溯源问答

**讲什么**：
> “解析完成后，我们问一个细粒度问题：‘Transformer 训练使用的 Adam 优化器 β1 和 β2 分别是多少？’”

> “答案不是直接生成，而是先经过 dense + sparse 双路检索，再用 RRF 融合。每个返回片段都带 page、paragraph、bbox。模型被强制要求每句话后挂 `[引#N]`。如果引用 ID 不存在，后处理会把它替换成 `[无依据]`；如果检索分数太低，就直接拒答。”

**为什么这么选**：
> “大模型会幻觉引用。我们不允许模型‘凭记忆’回答，必须基于检索到的片段，并且用后处理校验，把不可验证的引用显性化。拒答率本身也是我们衡量抗幻觉能力的指标。”

**屏幕操作**：
1. 进入“问答”页，输入问题，点击提问。
2. 答案出现后，点击 `[引#1: Attention Is All You Need p.8]`。
3. 弹出 PDF 查看器，第 8 页对应位置被黄色高亮框住。

**金句**：
> “评委可以看到，答案里的每一个结论，都能在 PDF 里找到原位的 bbox 高亮。”

---

## 3:00 - 4:00 第三步：引用图谱

**讲什么**：
> “单篇论文的问答还不够，科研更需要看关系。我们输入同一篇论文的 arXiv ID，构建引用图谱。节点大小代表这篇论文的引用含金量，边粗细代表引用关系的权重。”

> “这里我们利用 Semantic Scholar 的 `influentialCitationCount`，用 `log1p` 归一化。低于 0.1 的边被标记为 `is_perfunctory`，也就是应付式引用，会被过滤掉。”

**为什么这么选**：
> “传统引用图谱把‘被引次数’当影响力，但大量引用只是顺手一提。我们用 `influentialCitationCount` 刻画‘引用含金量’，帮助研究者快速找到真正重要的相关工作。”

**屏幕操作**：
1. 进入“图谱”页，输入 arXiv ID，点击构建。
2. 滚轮缩放、拖拽平移图谱。
3. 悬停节点显示影响力数值，点击节点打开原文 PDF。

---

## 4:00 - 5:00 第四步：综述生成

**讲什么**：
> “基于检索证据，我们可以一键生成文献综述。主题是‘Transformer 在机器翻译中的应用’。综述里每一句话都必须带 `[引#N]`，和 QA 一样做校验。”

> “生成后可以导出 Markdown，存入 MinIO，直接用于论文写作。”

**为什么这么选**：
> “综述最怕的就是模型把多篇论文的观点混在一起、张冠李戴。强制句句引用 + 后处理校验，确保综述里的每个论断都能回链到具体论文。”

**屏幕操作**：
1. 进入“综述”页，输入主题，点击生成。
2. 等待生成后，点击“导出 Markdown”下载。

---

## 5:00 - 6:00 第五步：绘图辅助

**讲什么**：
> “除了文字，科研还经常需要复现图表。我们支持用代码生成图表：输入数据和描述，后端会生成 matplotlib 或 mermaid 代码并渲染成 PNG/SVG。”

> “这里我输入一组准确率随训练轮数变化的数据，选择 matplotlib 折线图。生成后既能下载图片，也能下载代码，方便在论文里复现。”

**为什么这么选**：
> “文生图模型看着方便，但同 prompt 不同 run 可能不一样，没法审稿复现。代码生成是确定性的，配合 `temperature=0` 和请求哈希缓存，保证同输入同输出。”

**屏幕操作**：
1. 进入“写作”页，切到“绘图辅助”标签。
2. 选择图表类型，输入标题、描述、JSON 数据，点击生成。
3. 展示生成的 PNG 和代码，点击下载。

---

## 6:00 - 7:30 第六步：一键评测与 diff=0

**讲什么**：
> “最后也是最关键的一步：可复现性验证。我们在 4 份官方 PDF 上人工构建了 40 条 golden QA，覆盖 β1/β2、8×A100、BLEU 27.3、作者机构、参考文献条目等细粒度事实。”

> “执行 `make eval`，脚本会先检查 6 个服务健康，然后跑这 40 条问题，输出准确率、引用命中率、拒答率、平均延迟四项指标。最关键的是这个 `output_hash`。”

> “现在我再跑一次 `make eval`。可以看到 `output_hash` 完全一致，diff=0。”

**为什么这么选**：
> “比赛和审稿最担心的就是‘你这次跑和下次跑结果不一样’。`temperature=0` 消除了采样随机性，但 API 仍可能有微小波动。我们把每次输出按问题哈希缓存，二次运行直接复用，并生成 `output_hash`，确保可复现性可验证。”

**屏幕操作**：
1. 终端执行 `make eval`。
2. 展示生成的 Markdown 报告：准确率 100%、引用命中率 100%、拒答率 0%、平均延迟。
3. 再次执行 `make eval`，高亮两次 `output_hash` 相同。
4. 切回 TECH_DOC 里的并排图，指着图说：“这就是评委一眼能过的证据：左侧报告，右侧溯源高亮。”

---

## 7:30 - 8:00 收尾：三条主线

**讲什么**：
> “最后总结我们的三条主线：
> 1. **可验证**：每句话都带 `[引#N]`，无效引用显性化；
> 2. **可溯源**：点击引用即可回跳 PDF 原位，bbox 高亮；
> 3. **可复现**：`make eval` 一键评测，两次运行 diff=0。
>
> 谢谢大家。”

**屏幕操作**：停留在首页或并排图页面。

---

## 答辩 Q&A 预备

| 可能的问题 | 回答要点 |
|---|---|
| 如果 API 返回结果波动怎么办？ | 用缓存兜底：首次运行缓存输出，后续复用，生成 output_hash 验证 diff=0。 |
| 为什么不用更复杂的重排序模型？ | RRF 无参数、可解释、可复现，避免黑盒权重和训练数据依赖。 |
| 541 页书怎么保证不 OOM？ | 30 页子任务 + group/chord，图片直传 MinIO，子任务只返回元数据。 |
| 引用含金量怎么算？ | `influence_score = log1p(influentialCitationCount) / log1p(max_inf)`，阈值 0.1 过滤应付式引用。 |
| 如何保证图表可复现？ | 代码生成替代文生图，AST 白名单执行，请求哈希缓存图片。 |
