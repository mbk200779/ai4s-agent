# 2.22 综述导出 Markdown 的修复

## 1. 现象

点「导出 Markdown」，浏览器要么报下载失败，要么落下来一个 **21 字节**的文件，里面只有一行
`Internal Server Error`。换成英文主题又能正常导出——所以很容易被当成"偶发"。

后端日志给出的原因很直接：

```
File "starlette/responses.py", line 57, in <listcomp>
    raw_headers = [(k.lower().encode("latin-1"), v.encode("latin-1")) for k, v in headers.items()]
UnicodeEncodeError: 'latin-1' codec can't encode characters in position 33-37
```

## 2. 根因

HTTP 响应头**只能装 latin-1**，而导出接口把中文主题直接写进了 `Content-Disposition`：

```python
filename = f"{req.topic.replace(' ', '_')}.md"
headers={"Content-Disposition": f"attachment; filename={filename}"}
```

`综述：Transformer.md` 一个字节都塞不进 latin-1，整个响应在编码响应头时炸掉，
客户端拿到的就是 500。

顺带发现三个一起会坏的地方：

| 位置 | 问题 | 后果 |
| --- | --- | --- |
| 响应头 | 中文进 `filename=` | 500，下载失败 |
| 文件名 | 只替换了空格 | 主题含 `/ : * ? " < > \|` 时浏览器丢弃文件名或写入失败 |
| 前端 | `res.blob()` 不检查 `res.ok` | 服务端 500 时把错误页当成 .md 存盘，用户以为导出成功 |
| 前端 | `createObjectURL` 后立刻 `revokeObjectURL` | 句柄在下载启动前失效，点导出「没反应」 |

还有一条不是 bug、但导出后读不了的地方：正文里满是 `[引#N]`，在页面里能点开，
存成文件就只剩编号——**导出件无法追溯**。

## 3. 改法

### 3.1 文件名按 RFC 6266/5987 双写

新建 `backend/app/services/review/export.py`：

```python
def content_disposition(topic: str) -> str:
    stem = safe_stem(topic)
    ascii_name = f"review-{datetime.now().strftime('%Y%m%d')}.md"
    utf8_name = quote(f"{stem}.md", safe="")
    return f"attachment; filename=\"{ascii_name}\"; filename*=UTF-8''{utf8_name}"
```

- `filename=` 给只认 ASCII 的老客户端，固定 `review-YYYYMMDD.md`（带日期，多个综述存同一目录时不会被自动改名成 `(1)`）；
- `filename*=UTF-8''…` 给现代浏览器，中文按百分号编码，解回来就是原名；
- 前端优先读 `filename*`，读不到退回本地清洗过的名字。

`safe_stem` 同时处理三件事：Windows 禁用字符换 `_`、连续下划线折叠、按**字节**截断
（`_MAX_STEM_BYTES = 120`）。按字符截不够——一个汉字 3 字节，80 个汉字在 ext4 上就超了 255 字节上限。

### 3.2 导出件自带引用对照

导出请求新增可选字段 `refs`（前端把 `review.refs` 整个传过来），服务端在正文末尾追加：

```
## 附：引用对照（系统生成）

| 编号 | 论文 | 位置 | 片段类型 |
| --- | --- | --- | --- |
| 引#1 | Attention Is All You Need | p.1 · 3.2 Attention | 正文 |
| 引#2 | Attention Is All You Need | p.10 | 正文 |
```

几个细节都是为了「存到本地之后还能查」：

- **按编号升序**而不是正文出现顺序——附录是查表用的；
- 正文没出现的编号不列（不制造"有引用"的错觉）；
- 查不到记录的编号仍然占一行，标「（未记录）」，末尾再用一句话说明有几处——默默少一行等于让读者以为那句话没有出处；
- `kind` 翻译成中文（`paragraph`→正文、`table`→表格…），入库那套 `paragraph/chunk/chapter` 和另一些地方写的 `text` 都覆盖；
- 表格单元里的 `|` 转义、换行压平，否则一行会把整张表撑歪；
- `section` 抓成 arXiv 头（`arXiv:1706.03762v7 [cs.CL]`）时跳过，原样写只是把页码又说一遍；
- 手工上传的论文 ID 是 `upload_xxx`，不写进文献表——那是内部标识，不是 arXiv 号。`render_markdown` 的参考文献列表同步做了这个处理。

### 3.3 加 BOM

```python
def encode(markdown: str) -> bytes:
    return b"\xef\xbb\xbf" + markdown.encode("utf-8")
```

Windows 记事本靠 BOM 区分 UTF-8 与 ANSI，没有它中文全是乱码。主流 Markdown 解析器都容忍 BOM。

### 3.4 前端

```tsx
if (!res.ok) throw new Error(`HTTP ${res.status} · ${detail}`);
if (blob.size === 0) throw new Error('文件为空');
const name = filenameFrom(res.headers.get('Content-Disposition')) || fallbackName(review.topic);
...
window.setTimeout(() => window.URL.revokeObjectURL(url), 10000);
toast(`已导出 ${name}`, 'success');
```

失败时弹红条而不是静默存一个坏文件；成功时报出真正的文件名，用户能确认「拿到的是这一篇」。

## 4. 验证

**接口层**（`curl`，中文主题 + 特殊字符）：

```
code=200 size=3367
content-type: text/markdown; charset=utf-8
content-disposition: attachment; filename="review-20261110.md";
                     filename*=UTF-8''Transformer_%E6%B3%A8%E6%84%8F%E5%8A%9B%E6%9C%BA%E5%88%B6_%E7%BB%93%E6%9E%84%E4%B8%8E%E4%BB%A3%E4%BB%B7.md
首字节: ef bb bf 23 20 54 ...   # BOM + "# T"
```

边界：空 markdown → 400；不传 refs → 只有正文（附录不生成）；编号缺记录 → 「（未记录）」+ 汇总提示；
空主题 → `review.md`；`a/b\c:d*e?f"g<h>i|j` + 80 汉字 → `a_b_c_d_e_f_g_h_i_j_大语言模型…`（118 字节）。

**端到端**（headless Edge + CDP，页面上真实点按钮）：

```
review ready after 38s
export: clicked
toast: 已导出 Transformer_自注意力机制的优势与代价.md
downloads: [ 'Transformer_自注意力机制的优势与代价.md' ]
--- 3906 bytes  bom=true
    首行 "# Transformer 自注意力机制的优势与代价"
    含引用对照: true   对照行数: 4
```

## 5. 一个与代码无关的插曲

用 CDP 指定 `downloadPath` 测下载时，文件始终 `canceled`——排查后发现是 MSYS 把
`C:\Users\…` 改写成了 POSIX 路径，浏览器写不进去就静默取消。换成浏览器默认下载目录
（`~/Downloads`）后一次通过。**所以看到 "canceled" 先确认落盘路径，别急着改前端。**
