# 2.21 回答区字号体系

> 2026-11-10。把「可溯源问答」回答卡里的文字整体放大一档。

## 为什么改

回答区原来的字号是按「一屏塞下更多证据」设计的：正文 15px，检索片段预览 11px，
各类标签、阶段徽章、统计行全是 10px。信息确实密，但这一页的**主语是那段回答**——
用户是来读结论的，不是来扫仪表盘。10px 的 mono 标签在 1080p 屏幕上已经接近
「需要凑近看」的程度，而它们恰恰承载着「这段话可不可信」的判断信息。

## 映射

统一按等比放大，避免出现「正文大了、旁边标签还很小」的割裂：

| 原 | 现 | 用途 |
| --- | --- | --- |
| 9px | 10px | 角标内的 ✓ / ? 图标 |
| 9.5px | 11px | 表格/图表类型徽章 |
| 10px | 11.5px | 阶段徽章、RETRIEVAL/EVENT STREAM 标签、卡片 meta、统计行之外的元信息 |
| 11px | 12.5px | 检索片段预览、统计行 |
| 12px | 13.5px | 空态说明 |
| 13px | 14.5px | 被引用句、冲突说明 |
| 15px | 17px | **回答正文** |
| text-sm 14px | 15px | 「这次没有作答」等小标题 |
| text-base 16px | 17→18px | 回答卡内的问题标题 |

正文行高仍是 `leading-[1.85]`，放大后约 31.5px，中文长段落不挤。

## 改了哪些文件

- `components/answer/StreamAnswer.tsx`：正文、阶段徽章、检索列表、统计行、事件流、折叠条
- `components/answer/confidence.tsx`：置信档位 pill、配置行、逐句明细
- `components/answer/uncertainty.tsx`：空检索卡、冲突面板、未识别提示、判定依据
- `components/RoutingTrace.tsx`：检索计划条（分流理由、命中规则、召回统计）
- `app/qa/page.tsx`：回答卡内的问题标题与 `Q.01` 序号、原文弹窗里的被引用句

没动的：页头、输入框与提示文案、推荐问题、底部状态条——它们是页面外壳，
放大反而会让首屏更拥挤。

## 一个连带修正

字号变大后，390px 窄屏上「阶段徽章 + TRACE」挤在一行会把四个徽章压成
四行竖排。给这行加 `flex-wrap` 后 TRACE 自动落到下一行，徽章变成 2×2。

## 验证

用 CDP 读回答卡内每个含文本元素的 `getComputedStyle().fontSize`：

```
18px   ×1   β2 的取值是多少？        ← 问题标题
17px   ×1   β2 的取值是 0.98         ← 正文
13.5px ×2   表格结构未复原           ← 未识别说明
12.5px ×11  Table 2: The Transformer…  ← 检索预览
11.5px ×44  Q.01 / 理解 · 596ms      ← 标签与元信息
11px   ×2   表格                    ← 类型徽章
```

- 1440px：卡片 `scrollWidth === clientWidth`，无横向溢出；
- 390px：`documentElement.scrollWidth = 390`，无元素超出视口；阶段徽章 2×2；
- 截图核对：检索卡片两列未截断，统计行不换行错乱，角标未压到正文。
