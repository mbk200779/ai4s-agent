# 12 · 不确定性状态设计

> 一句话：**把「不知道」拆成三种具体形态，每种形态说清断在哪、看到什么、下一步做什么。**

## 1. 问题：三种「不知道」原来共用一个出口

旧链路只有两个出口：作答，或者一句「未检索到相关片段，无法回答」。

这句话把三件完全不同的事压成了同一句：

| 断在哪一层 | 用户真正想知道的 | 结果 |
| --- | --- | --- |
| 库里没有这个概念 | 是我问错了，还是你们没有这批文献？ | 一律「无法回答」，用户只能重问一次碰运气 |
| 两篇论文给了不同的值 | 到底哪个对？为什么不一样？ | 模型挑一个写进答案，或者含糊其辞绕过去 |
| 片段是空表格 / 只有图注 | 这句话是不是从一张没解析的表里猜出来的？ | 照常作答，还带着页码和分数，看起来完全像证据 |

第三类最危险：它不是"没答"，是**答了但证据是空的**。这类问题不会走到拒答分支，
因为检索确实召回了片段、分数也不低——只是片段内容是 `| | | |`。

### 与 07（分级置信）的分工

这两件事必须分开，否则会互相稀释：

| | `confidence`（07） | `uncertainty`（12） |
| --- | --- | --- |
| 判什么 | 这一句结论**有多少证据支撑** | 证据本身**能不能用** |
| 前提 | 假设证据本身是清楚的 | 就是来检查这个前提的 |
| 取值 | 已验证 / 需核对 / 证据不足 | 空检索 / 冲突 / 未识别 |
| 回答的问题 | 这句话我敢不敢直接引用 | 我看到的这段东西是什么 |

一句话可以是 `verified`（原文明确写着）却落在一张没复原的表格上——
此时两个状态**同时显示**。所以这不是 07 的"第四档"，是另一根轴。
`uncertainty` 判空时 `confidence` 返回 `applicable=false`，两者不冲突。

## 2. 三类判定条件（交付物 1）

### 2.1 总表

| 状态 | 判据 | 存储字段 | 是否阻断生成 |
| --- | --- | --- | --- |
| `empty` | ① 一条都没召回；② 或「最具体的两个词在库内 df=0」且检索分偏低；③ 或「没有任何一段同时出现 ≥2 个关键词」 | `uncertainty.empty` | 是（`blocking=true`） |
| `conflict` | 同一符号/指标在 ≥2 篇论文取到不同值；或同一对象上两段结论方向相反 | `uncertainty.conflicts[]` | 否 |
| `unreadable` | 召回/引用的片段是空壳表格、只有图注、模板图注、扫描页 | `uncertainty.unreadable[]` | 否 |

`states` 是这三者的子集列表，前端拿它做「有没有东西要显示」的总开关；
三类可以同时出现（比如答案引用了 ViT p7 的空表格，同时 β2 又与另一篇冲突）。

### 2.2 空检索：不能按「召回了几条」判

**dense 检索永远会返回最近邻。** 实测「蛋白质折叠的自由能垒是多少？」召回了 6 段，
融合分 0.8572（归一化后看着很高），最近邻是光纤孤子论文里的「free energy」段落。
如果判据是"零片段"，这个状态在真实语料上**一次都不会触发**。

真正该说"没有"的时刻，是**问句里最具体的词在库里一次都没出现过**——那些近邻不是证据。

#### 判据必须看「同段共现」，而不是「任一词命中」

问句译成英文后是 `free / energy / barrier / protein / folding`，其中：

| 词 | 库内命中段数 |
| --- | --- |
| free | 5 |
| energy | 5 |
| barrier | 2 |
| protein | **0** |
| folding | **0** |

按"命中一个就算找到"，这句永远判不成空检索（`free energy` 在光纤论文里是正经术语）。
所以用双闸门：

```python
def _coverage(chunks, terms) -> tuple[int, int]:
    """单段最多同时命中几个词 / 有多少段至少命中一个。"""
    best, any_hit = 0, 0
    for rec in chunks:
        hay = _payload_text(rec.get("payload") or {}).lower()
        n = sum(1 for t in terms if t in hay)
        if n:
            any_hit += 1
            best = max(best, n)
    return best, any_hit
```

```python
need = min(2, len(terms))                  # 只有一个词时退化成"它自己有没有"
rare = sorted(terms, key=lambda t: (counts.get(t, 0), -len(t)))[:2]
rare_missing = bool(rare) and all(counts.get(t, 0) == 0 for t in rare)
no_coverage = coverage < need

if sources:
    if not no_coverage and not (rare_missing and retrieval_weak):
        return None                        # 正常作答
```

- `rare` 取 **df 最低的两个词**（同分取更长的，长词更具体）——问句里总有泛词，
  盯"有没有任一词命中"必然漏判。
- `no_coverage`（一段都凑不出两个词）与分数无关，直接判空：这批片段不是证据，排序再好也不是。
- `rare_missing` 只说明"最具体的词不存在"，还要求 **检索本身偏弱**才认，否则可能是排序不好。
  `retrieval_weak` 看的是**重排前的原始融合分**（`0.013818 < 0.015`）；
  归一化后的 `score` 最大值恒为 1，拿它判高低会永远判"有把握"。

#### 三种 reason，三种下一步

| reason | 何时 | 文案 | 下一步 |
| --- | --- | --- | --- |
| `no_corpus` | 库内 0 段 | 库内还没有可检索的正文 | 去上传论文 |
| `no_lexical_hit` | 关键词在库内 0 命中 | 关键词在库内没有出现过 | 用改写建议重问 |
| `no_hits` | 关键词在库内，但一条没召回 | 这次检索没有召回任何片段 | 用改写建议重问 / 重试 |

三者混成一句"无法回答"，用户就无法判断该换问法还是该补文献——而这正是他唯一能采取的行动。

#### 为什么判空要跳过生成

库里确实没有的东西，让模型拿着 6 段近邻去写，它只会写出"根据现有资料无法确定"
这种既不像拒答也不像答案的东西。`blocking=true` 时 `qa_service` 直接返回，
`reject_reason` 用 `reason_text()` 生成一句**可核对的事实**：

> 在库内 5 篇论文的 279 个片段里，「protein」、「folding」 一次都没出现，
> 没有任何一段同时出现你问的两个关键词（最高 2 个），因此没有作答。

刻意不含"无法回答"：这句话要让用户能自己复核"是不是真的没有"。

#### 关键词提取的两个细节

- `_LATIN_STOP` **不**过滤 `model / paper / method / task` 这类词。
  它们在问句里是内容词（"which model is better" 的 model 就是被问的对象），
  滤掉会让"关键词全 miss"在没有内容词时误触发。
- 中文问句只切出实词片段用于**展示**（"你原本问的是这几个词"），不参与命中判定——
  库内正文是英文，拿中文去数命中率恒为 0，会把每一句中文问句都判成空检索。

### 2.3 证据冲突：只并列，不裁决

四类，各有各的"为什么不是错"：

| type | 含义 | 判定要点 |
| --- | --- | --- |
| `value_diff` | 同一符号取值不同 | 符号 + 明确赋值符 + 可解析的数值，且来自不同论文 |
| `polarity` | 结论方向相反 | 对象有拉丁专名交集 + 方向词相反 + 来自不同论文 + 无共同条件标记 |
| `conditional_split` | 条件性分歧 | 同上，但有一边带「在/当/如果/小数据/大数据」 |
| `scope_mismatch` | 同名不同义 | 值相同但量纲不同 → 不是冲突，单独进 `ambiguous` |

#### 取值抽取必须要求明确的赋值关系

只看"符号附近有数字"会读错，两个真实反例决定了正则能收哪些词：

| 原文 | 错误读法 | 原因 |
| --- | --- | --- |
| `β2 and β3 = 0.1 ps2/nm/km` | β2 = **3** | 那是 β3 的下标 |
| `β2 of 10 m SMF` | β2 = **10 m** | 那是光纤**长度**，真值在句末 −20 ps/nm/km |

```python
# 只认明确赋值：= : | is was set to taken as。删掉了 of。
_ASSIGN_RE = re.compile(r"\s*(?:=|:|＝|\||is\b|was\b|were\b|set\s+to|taken\s+as)\s*", re.I)
```

代价是"β2 取 0.98"这类纯散文写法读不到。可以接受：**读不到只是少一处提示，读错会报一处假冲突**，
两者代价不对称——一次假冲突会让用户开始怀疑一条本来正确的答案。

#### 量纲分组：区分「取值冲突」与「同名不同义」

β2 = 0.98（无量纲，Adam 二阶矩衰减）与 β2 = 0.1 ps²/nm/km（色散系数）
是**两个不同的物理量**，并列成"冲突"是错的。所以按单位分组，跨组进 `ambiguous`：

> 库内另有一篇论文用「β2」表示带单位的另一个物理量。

#### 方向冲突：条件标记优先于对立

`Transformer 和 CNN 哪个更好？` 的答案里，「当数据量不足时…可能表现不如 CNN。
然而，在大规模训练的情况下…超越…」——两边都带条件，判 `conditional_split` 而不是 `polarity`。
这是正确行为：**单句内自带条件不是两篇论文的矛盾**。

同理，整条答案只有 1 条 claim 时，同批里没有第二句可比，`states` 为空。
漏报比误报便宜：宁可少提一次，不要在两篇其实一致的论文之间造一个"矛盾"。

#### 实测输出（`β2 设为多少`）

```
dimension: β2 的取值
结论 A  β2 = 0.98    Attention Is All You Need · p.7
         optimizer [20] with β1 = 0.9, β2 = 0.98 and ϵ = 10−9...
结论 B  β2 = 0.999   BERT · p.13 ＋ ViT · p.5
         learning rate of 1e-4, β1 = 0.9, β2 = 0.999, L2 weight decay of 0.01...
不下判断  两边都是各自论文里的实验设置。系统不判断哪个值适用于你的问题——
          那取决于你要复现哪一篇。
```

B 侧合并了两篇论文，因为它们取同一个值——**不是"两篇对一个"，是两票同一个答案**。

### 2.4 表格 / 图表未识别：四类，四种补救

```python
def classify_chunk(text, kind, anchors) -> str | None:
    if doc.get("text_layer") is False or doc.get("precision") == "ocr":
        return "scan_page"
    if kind == "table":
        cells = [c for c in _CELL_SPLIT.split(body) if c.strip()]
        if len(cells) <= 3 or not re.search(r"\d", body):
            return "table_empty"
    if kind == "figure":
        if body.startswith("该图表"):
            return "figure_synthetic"
        if re.match(r"^(?:FIGURE|Figure|Fig\.?)\s*\d", body):
            return "figure_caption_only"
    return None
```

| kind | 片段长什么样 | 为什么危险 | 补救 |
| --- | --- | --- | --- |
| `table_empty` | `\|`、`\| \| \| \| \|`、`BER \| T B \| ERT` | 数字在页面上，但没进文本 | 查看原页 |
| `figure_caption_only` | 只有 `Figure 3: ...` 一行 | 图里的曲线从来没被解析过 | 查看原页 |
| `figure_synthetic` | 以「该图表」开头 | **最危险**：模板回填的文案，看起来像原文 | 查看原页 + 明说不是原文 |
| `scan_page` | `text_layer=false` / `precision=ocr` | 文字来自 OCR，字符与结构可能有错 | 查看原页 |

本语料实测（279 段 / 5 篇）：`table 80 / figure 69 / reference 66 / paragraph 63 / chapter 1`，
其中 table 命中空壳 **52/80**，figure 命中 **65/69**（63 段只有图注 + 2 段模板文案）。
`scan_page` 当前为 0（本批论文都有文本层），该分支靠离线用例覆盖。

#### 只报「本次真的碰过的」

一次回答只用 6 段。列出全库 52 段空表格是系统自检报告，不是"这次回答要注意什么"。
过滤条件 = **被本次回答引用的 chunk，或与被引用论文同篇的 chunk**：

> 回答引用了 ViT 第 6 页，那么同一篇第 7 页的空表格值得提醒（它就在旁边，用户很可能顺手翻到）；
> 但检索顺带捞到的一篇无关论文的空表格不是这条回答的不确定性，是噪声。

这条过滤是实测出来的：孤子分子问题里原本会带出一条 ViT p18 的空表格。

#### 两个小坑

- `cells` 对 figure 是**假数**：拿分隔符硬切图注得到的"2 个单元格"毫无意义，非 table 一律 `None`。
- `cited` 决定排序与视觉权重：影响过回答的排前面（"你刚看到的结论可能不准"），
  其余只是"顺带一提"，用虚线灰边。

## 3. 状态怎么随响应返回

### 3.1 响应结构

```json
"uncertainty": {
  "version": "unc-v1.0.0",
  "states": ["empty"],
  "empty": { "reason": "no_lexical_hit", "blocking": true,
             "scope": {"papers": 5, "chunks": 279, "by_kind": {...}, "titles": [...]},
             "query": {"terms": [{"term": "protein", "chunks": 0, "hit": false}, ...],
                       "coverage": {"best_chunk_terms": 2, "chunks_any": 11, "rare": ["protein","folding"]},
                       "top_raw_score": 0.013818, "threshold": 0.015, "zh_terms": [...]},
             "nearest": [...], "suggestions": [...], "action": {"type": "rewrite", "label": "用建议改问"} },
  "conflicts": [], "unreadable": [],
  "checked": {"empty": true,
              "conflict": {"ran": true, "symbols": ["beta2"], "claims": 5},
              "unreadable": {"ran": true, "sources": 6}},
  "rules": [...]
}
```

### 3.2 `checked`：区分「没检测」与「检测了没发现」

冲突检测只在问句里带符号、或已经有 claim 时才跑。界面上一律写"已检测"是假的，
所以 `checked.conflict.ran` 单独记录，`symbols` / `claims` 说明这次到底拿什么去比的：

> 空检索 **已检测** · 冲突 **未检测** · 未识别 **已检测（8 段）** · unc-v1.0.0

「未检测」和「检测了没发现」对用户的意义不同：前者是"这次没查"，后者才是"查了，没有"。

### 3.3 SSE：先发 partial，`done` 给权威版

```
event: uncertainty   {"states": ["unreadable"], "partial": true, ...}
event: claim         ...
event: done          {"uncertainty": {...含 conflicts...}}
```

空态与未识别是**证据层事实**，不必等正文生成完。先发一份，让读者在等答案的三秒里
就知道材料有问题；`done.uncertainty` 是权威版（多了冲突，它要等 claim 出来才判得了）。

前端只做覆盖，不做合并推理：

```ts
case 'uncertainty':
  return { ...prev, uncertainty: data as unknown as Uncertainty };
case 'done':
  return { ...prev, done, uncertainty: done.uncertainty ?? prev.uncertainty };
```

## 4. 三个界面组件（交付物 2）

### 4.1 空检索卡（`EmptySearchCard`）

![空检索](../assets/uncertainty/02_empty_card.png)

信息顺序是刻意排的：**先给范围，再给关键词，最后才给建议**。

1. 标题「关键词在库内没有出现过」——先把结论说出来，不铺垫。
2. 四个统计格：论文 5 / 片段 279 / 检索类型 point / 同段最多命中 2/5。
   这一行是「我们真的找过了」的证据。反过来先说"你换个说法试试"，
   会读成在怪用户。
3. 关键词 chip：`free 5 段` `energy 5 段` `barrier 2 段` `protein 0 段` `folding 0 段`。
   未命中标红、`0 段` 直接写在 chip 上——用户一眼看到是哪两个词没有。
   下面附一行 `实际检索文本：What is the free energy barrier of protein folding?`，
   说明系统不是拿中文去查英文库。
4. 改写建议按钮：**主行就是点下去会提交的那一句**（`Attention Is All You Need 的主要贡献是什么？`）。
   只写"改问某篇"这种摘要，用户点之前不知道要问什么，等于让他盲签。共用理由只说一次。
5. 「看看最接近的 3 段（不是证据）」——折叠。给想自己核对的人看系统到底捞到了什么，
   同时明确它们不是证据。

![点建议之后的回答](../assets/uncertainty/03_after_suggestion.png)

点第一条建议后真的提交了第二个问题并拿到答案——下一步动作是可用的，不是装饰。

### 4.2 冲突面板（`ConflictPanel`）

![证据冲突](../assets/uncertainty/05_conflict_card.png)

完全对称的两栏（`sm:grid-cols-2`），视觉上不给任何一边更高权重：

- 每栏：`结论 A/B` → 取值（等宽字体，最大字号）→ 论文名 · 页码 → 原文引文 → `看原文 ↗`
- 底部一行「**不下判断** 两边都是各自论文里的实验设置。系统不判断哪个值适用于你的问题——那取决于你要复现哪一篇。」
- `ambiguous` 有内容时在下面单独说明（"另有一篇论文用 β2 表示带单位的另一个物理量"）。

「不下判断」不是免责声明，是**能力边界的诚实陈述**：系统没有"你要复现哪篇"这个信息，
给一个它猜的答案比给两个真答案更糟。

### 4.3 未识别提示（`UnreadableNotice`）

![表格结构未复原](../assets/uncertainty/07_unreadable_card.png)

一行一条，密度高但每条都带页码与动作：

```
UNREADABLE · 表格与图表   1 处 · 均未影响本次回答
表格  表格结构未复原   p.7 An Image is Worth 16x16 Words: …
      这一页的表格只抽到了分隔线，单元格里的数字没有还原出来，表格结构未复原。  查看原页 ↗
```

- 卡头计数区分两种情形：`N 处 · 均未影响本次回答` / `X 处影响本次回答`。
  上一版写「0 处影响本次回答」，读起来像"没有影响"，但其实是在报一处它们自己也说不清的事。
- `cited=true` 的用实线红边并排在最前；其余虚线灰边。
- 每条都有 `查看原页 ↗`——四类未识别的补救方式都是同一个：看原页。

![查看原页](../assets/uncertainty/08_open_page.png)

点「查看原页」直接跳到 PDF 第 7 页，就是那张没复原的表。**不能只提示不给路。**

### 4.4 判定依据（`UncertaintyRules`）

![判定依据](../assets/uncertainty/09_rules.png)

默认折叠，头部一行就是这次的检测状态（见 3.2）。展开后每条规则给三行：
`判据 / 为什么 / 下一步`。这段文案来自后端的 `RULES`，与代码里的判据同源——
判据只写在代码里、界面上看不见，就等于黑盒。

`RULES` 里的篇数在 `_rules()` 里填真实值（「库内这 5 篇论文」）。
上一版写死成「这 N 篇」，界面上就真的显示一个字母 N。

## 5. 兜底文案表（交付物 3）

全部集中在 `uncertainty.py` 的 `COPY`，前端不再自己拼句子。

| key | title | detail |
| --- | --- | --- |
| `empty.no_corpus` | 库内还没有可检索的正文 | 这个课题下没有已解析完成的论文片段，检索无从谈起。 |
| `empty.no_lexical_hit` | 关键词在库内没有出现过 | 检索到的片段只是向量空间里的近邻，不是证据——问句里最具体的词，在库里一次都没出现过。 |
| `empty.no_hits` | 这次检索没有召回任何片段 | 关键词在库内出现过，但检索链路没把片段召回，属于系统侧的问题而不是库里没有。 |
| `unreadable.table_empty` | 表格结构未复原 | 这一页的表格只抽到了分隔线，单元格里的数字没有还原出来，表格结构未复原。 |
| `unreadable.figure_caption_only` | 只读到图注 | 图里的曲线、柱子和标注是像素，不是文本；能读到的只有图题那一行。 |
| `unreadable.figure_synthetic` | 图注是系统生成的 | 原文这一页没有可提取的图题，这段说明是入库时由模型生成的模板文案，不是原文。 |
| `unreadable.scan_page` | 该页为扫描件 | 该页为扫描件：没有文本层，文字来自 OCR，个别字符与表格结构可能有错。 |

三条 `reject_reason`（给老前端/老字段用的单句摘要，`reason_text()` 生成）：

| reason | 实测文案 |
| --- | --- |
| `no_corpus` | 这个课题下还没有已解析完成的论文片段，检索无从谈起。 |
| `no_lexical_hit` | 在库内 5 篇论文的 279 个片段里，「protein」、「folding」 一次都没出现，没有任何一段同时出现你问的两个关键词（最高 2 个），因此没有作答。 |
| `no_hits` | 在库内 0 篇论文的 0 个片段里，这次检索没有召回任何可用的内容。 |

### 为什么不用「抱歉，我无法回答」

不是措辞偏好，是信息量问题：

| 写法 | 用户能得到的行动 |
| --- | --- |
| 抱歉，我无法回答 | 无。只能重问一次碰运气，或者干脆走开 |
| 在库内 5 篇 279 段里，「protein」「folding」一次都没出现 | 换词、拆句，或确认库内没有这个方向 → 于是有了改写建议按钮 |
| 两边取值不同，各自论文与环境都在 | 去看自己复现的是哪一篇 → 于是有了并排原文 |
| 该页表格结构未复原 | 自己翻到 p.7 看那张表 → 于是有了查看原页 |

**每一类状态都必须落到一个用户能执行的动作上**，否则"诚实"只是把问题退回给用户。
三类状态的动作分别是：`rewrite`（改问）、`compare_pages`（并排看原文）、`open_page`（看原页），
随响应一起返回，前端的按钮直接读它。

## 7. 踩坑记录

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| dense 永远返回最近邻 | 「零片段」判据在真实语料上一次都不触发 | 改成"关键词在库内有没有" |
| 「任一词命中」判空失效 | `free energy` 在光纤论文里能命中 5 段，空检索永远判不出来 | 加 `_coverage`（同段共现）+ `rare`（df 最低两词）双闸门 |
| `β2 and β3 = 0.1` 抽出 3 | 那是 β3 的下标 | `_ASSIGN_RE` 要求明确赋值符 |
| `β2 of 10 m SMF` 抽出 10 m | 那是光纤长度，真值在句末 | 删掉 `of`，不再当赋值符 |
| figure 的 `cells: 2` | 拿分隔符硬切图注，得到毫无意义的"单元格" | 非 table 一律 `None` |
| 未识别把无关论文也报出来 | 孤子问题里冒出 ViT p18 的空表格 | 加 `cited_papers` 过滤 |
| `checked` 写成两态 | "没检测"被说成"已检测" | `ran` 单独记录，界面显示「未检测」 |
| 规则文案留 `这 N 篇` | 界面上真的显示字母 N（截图 09） | `_rules()` 填真实篇数，加离线断言 |
| 三条建议重复同一句理由 | 看起来像模板生成 | 共用理由提到组上面说一次 |
| `coverage` 字段被 Pydantic 丢掉 | 响应里 `coverage: null` | `EmptyQuery.coverage: Dict[str, Any]` |
| `docker exec ... python /app/x.py` 报路径不存在 | Git Bash 把 `/app` 改写成 `D:/安装包/...` | `MSYS_NO_PATHCONV=1` |
