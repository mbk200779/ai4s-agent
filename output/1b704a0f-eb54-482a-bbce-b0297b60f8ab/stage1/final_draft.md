## （1）项目详细介绍及使用方式

### 一、项目简介

**AI4S 学术研究 Agent** 是一个面向科研人员的一站式智能文献研究平台。科研人员每天需要阅读大量 PDF 论文并提取细粒度事实（超参数、实验结果、作者机构、参考文献等），传统大模型问答存在两大致命问题：**幻觉引用**（编造不存在的来源）和**无法复现**（同一问题多次询问结果不一致）。

本作品以 **"可验证、可复现、可溯源"** 为核心目标，覆盖科研工作全流程：

- **论文入库**：支持 PDF 上传与 arXiv ID 在线导入，自动完成细粒度结构化解析（章节树、段落、图表、公式、表格、参考文献）；
- **可溯源问答**：基于检索增强（RAG）的问答，每句话强制标注 `[引#N]` 引用，点击可跳转 PDF 原文并高亮对应位置；
- **跨文献推理**：最多 3 跳的子问题迭代检索，自动发现多篇论文之间的矛盾点；
- **引用图谱**：基于 Semantic Scholar / OpenAlex / Crossref 构建引文网络，用"引用含金量"算法过滤应付式引用；
- **综述生成**：自动生成句句带引用的结构化文献综述，可导出 Markdown；
- **写作与绘图辅助**：生成论文大纲；绘图采用 matplotlib/mermaid **代码生成**（而非文生图模型），保证同输入同输出；
- **一键评测**：40 条金标准问答数据集，自动生成含准确率、引用命中率、拒答率、平均延迟的评测报告，两次运行 `output_hash` 严格一致（diff=0）。

### 二、系统架构

系统采用前后端分离 + 微服务化部署，共 6 个 Docker 服务，一条命令 `make up` 一键启动：

| 服务 | 技术栈 | 职责 |
|---|---|---|
| web | Next.js 14（React + TypeScript） | 前端交互，端口 3000 |
| api | Python + FastAPI + Uvicorn | 后端 API，端口 8000 |
| worker | Celery | 异步 PDF 解析与索引 |
| qdrant | Qdrant 向量数据库 | dense + sparse 双路向量存储 |
| minio | MinIO 对象存储 | PDF / 图片 / 溯源日志存储 |
| redis | Redis | 任务队列与缓存 |

### 三、使用方式

1. **环境准备**：安装 Docker Desktop，复制 `.env.example` 为 `.env` 并填入大模型 API Key；
2. **一键启动**：项目根目录执行 `make up`，等待 6 个服务全部 healthy；
3. **访问系统**：浏览器打开 `http://localhost:3000`；
4. **上传论文**：在首页上传 PDF（或输入 arXiv ID 在线导入），系统自动解析入库；
5. **提问**：进入"问答"页输入问题（中英文均可），获得带 `[引#N]` 引用的回答，点击引用即可查看 PDF 原文高亮；
6. **进阶功能**：在"图谱"页查看引用网络、"综述"页生成文献综述、"写作"页获取大纲与图表、"评测"页运行可复现评测。

**实测示例**（真实运行记录）：上传一篇光纤激光器领域论文后提问"这篇论文研究的是什么物理现象？"，系统返回：

> 这篇论文研究的是光纤激光器中各种阶数的孤子分子（soliton molecules）的产生与演化现象 [引#2: 论文标题 p.1]。

点击引用标注即可在 PDF 原文中高亮定位到对应段落，实现"每句话都有出处"。

## （2）项目的亮点

### 亮点一：可溯源——每句话都有出处，拒绝幻觉引用

- 答案的每句话末尾**强制**标注 `[引#N]` 引用编号；
- 后处理逐条校验：引用编号不存在则替换为 `[无依据]` 并记录，绝不静默放行；
- 引用可点击跳转 PDF 原文，按 page/bbox 精确高亮到段落级位置；
- 每次问答的完整溯源日志（query、answer、sources、页码、bbox）写入对象存储，可审计、可回查。

### 亮点二：拒答机制——"不知道"比"编造"更有价值

- 检索为空或置信度低于阈值（RRF 分数 < 0.03）时**直接拒答**而非编造；
- 把"拒答率"作为可量化的抗幻觉指标纳入评测报告。

### 亮点三：可复现——从模型承诺变成工程验证

- LLM temperature 固定为 0，消除采样随机性；
- 评测脚本缓存每条 QA 的实际输出，二次运行直接复用并生成 `output_hash`；
- **两次评测运行 diff=0**，可现场验证。

### 亮点四：双路融合检索——可解释的 RRF 架构

- dense 语义向量（1024 维多语言模型）+ sparse BM25 关键词双路召回；
- Reciprocal Rank Fusion（k=60）无参数融合，不训练、不调权重，结果稳定可解释。

### 亮点五：引用含金量算法——过滤"应付式引用"

- 不采用简单的被引次数，而是基于 `influentialCitationCount` 计算对数归一化影响力分数；
- 低于阈值的引用边自动标记并过滤，帮助研究者快速定位真正关键的工作。

### 亮点六：代码生成绘图——确定性替代随机性

- 图表由 matplotlib / mermaid 代码渲染，而非文生图模型；
- 代码在沙箱环境（AST 白名单 + 安全 builtins）中执行，保证安全；
- 请求内容哈希作为缓存键，同输入同输出。

### 亮点七：端到端一站式科研工作流

- 上传 → 解析 → 问答 → 推理 → 图谱 → 综述 → 绘图 → 评测，全流程覆盖；
- 6 服务 Docker Compose 一键编排，`make up` / `make eval` 两条命令完成部署与验收。

## （3）AI 测试技术落地使用情况概述

本项目在开发与验证过程中，系统性地应用了 AI 测试技术，确保 LLM 应用的质量可度量、可回归：

### 1. 金标准问答数据集（Golden QA）

- 构建了 **40 条细粒度事实型问答**数据集（`backend/eval/golden_qa.json`），覆盖 4 篇论文的章节树、实验数值、方法对比等维度；
- 每条数据包含问题、预期答案关键子串，用于自动化断言。

### 2. 自动化评测流水线

- `make eval` 一键执行：健康检查 → 40 条 QA 逐条调用 → 指标计算 → Markdown 报告生成；
- 量化指标包括：**准确率**（答案包含全部预期子串的占比）、**引用命中率**（带有效 `[引#N]` 的占比）、**拒答率**（检索无支撑时的拒答占比）、**平均端到端延迟**。

### 3. 可复现性测试（diff=0 验证）

- 利用输出缓存机制，连续两次评测的 `output_hash` 严格一致；
- 已实际运行两轮评测（run1 / run2），结果可对比、可回归，为每次代码改动提供回归基线。

### 4. 拒答即测试

- 将"检索无支撑时的拒答"作为测试断言的一部分：对超出语料范围的问题，系统必须拒答而不是编造——这本身是一项被自动化验证的功能。

### 5. 真实环境端到端验证

- 在 Windows + Docker Desktop 环境完成 6 服务全栈部署验证（全部 healthy）；
- 以真实论文（光纤激光器孤子分子研究）完成"上传 → 解析 → 中文问答 → 引用溯源"端到端验收，问答结果带精确页码引用。

## （4）项目中涉及的关键技术

| 关键技术 | 具体实现 |
|---|---|
| **检索增强生成（RAG）** | dense（多语言 embedding，1024 维）+ sparse（BM25）双路召回，RRF（k=60）融合排序 |
| **强制引用与后处理校验** | 正则解析 `[引#N]`，逐条校验引用 ID 存在性，无效引用降级为 `[无依据]` |
| **多模态文档解析** | PyMuPDF + pdfplumber 文本/布局解析；vision LLM 识别公式转 LaTeX、生成图表说明 |
| **异步任务编排** | Celery group/chord：长文档按 30 页拆分子任务并行解析，回调合并去重 |
| **向量数据库** | Qdrant named vectors 同时存储 dense/sparse 向量，支持混合检索 |
| **去重算法** | 三层去重：arxiv_id+version 唯一键 → 全文 SHA256 → embedding 余弦相似度（阈值 0.96） |
| **LLM 统一抽象** | LiteLLM 统一接入 GPT / Claude / Qwen，temperature=0 保证确定性；Prompt 集中管理并带版本号 |
| **Prompt 版本管理** | 所有 Prompt 集中于 PROMPTS 字典，按 PROMPT_VERSION 索引，升级必须新增版本号，历史溯源日志可解释 |
| **沙箱代码执行** | 绘图代码经 AST 白名单解析 + 安全 builtins 环境执行，杜绝任意代码执行 |
| **前后端分离与容器化** | FastAPI + Next.js + Docker Compose 6 服务编排，healthcheck 全覆盖 |
| **PDF 前端溯源** | pdf.js 动态渲染，按 page/bbox 绘制高亮框，点击引用回跳原文 |

## （7）若项目是在其他项目基础上优化，请说明优化部分

**本作品并非基于其他参赛项目或开源项目二次开发，而是从零自研的完整系统。**

需要说明的是，开发过程中使用了业界成熟的开源基础组件作为**基础设施**（这属于正常的工程实践，而非项目基础）：

| 组件 | 用途 | 说明 |
|---|---|---|
| FastAPI / Next.js | Web 框架 | 通用开发框架 |
| Qdrant / MinIO / Redis | 存储与队列 | 通用基础设施，均以 Docker 容器部署 |
| fastembed | embedding 推理 | 仅用于生成文本向量 |
| LiteLLM | LLM API 抽象层 | 统一多家 LLM 的调用接口 |
| pdf.js | 前端 PDF 渲染 | 浏览器端 PDF 显示组件 |

**本作品的核心创新部分均为自主设计与实现**，包括但不限于：

1. 可溯源抗幻觉问答链路（强制引用 → 后处理校验 → 拒答机制 → provenance 日志）；
2. dense + sparse + RRF 双路融合检索架构与三层去重策略；
3. 引用含金量算法（influentialCitationCount 对数归一化 + 应付式引用过滤）；
4. 基于 group/chord 的长文档分布式解析流水线；
5. 缓存兜底的可复现评测体系（output_hash / diff=0）；
6. 跨语言检索优化（中文提问自动翻译检索、中文作答）。
